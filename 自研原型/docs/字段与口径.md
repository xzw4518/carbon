# 字段与口径（v2 · 2026-11-25）

> 唯一真相源：MySQL 库表（36 张业务表）。接口是读出口，前端只展示，不再持有第二份数据。
> 本表登记 P0 口径字段：**概念 → 表.列 → 谁写 → 谁读 → 口径 → 真相源**。新增/改名字段必须补行并重跑 `tools/data-check.sh`。
> 双字段一致性由 29 项数据门禁断言（`platform/backend/tools/data-check.sh`），不允许只靠人同步。

## 0. 通用约定

| 约定 | 规则 |
|---|---|
| 租户隔离 | 所有业务表带 `org_id`；查询由 `TenantLineInnerInterceptor` 自动加条件，豁免表见 `multi-tenancy.md` |
| 软删除 | `disabled=1` 表示停用/删除；列表默认 `disabled=0`，物理删除只允许测试数据 |
| 乐观锁 | `version` 每次更新 +1；PATCH 必须回传，不一致返回 `VERSION_CONFLICT` |
| 操作留痕 | `created_by/updated_by` 存手机号；关键动作另写 `audit_log` |
| 时间 | 日期 `YYYY-MM-DD`；月份 `YYYY-MM`；时间戳 `YYYY-MM-DD HH:mm:ss`（接口 ISO-8601） |
| 排放量 | `DECIMAL`，单位 tCO₂e，展示 3 位；写库不四舍五入到整数 |
| 金额 | 单位万元，`DECIMAL(18,2)`；交易单价 2 位、金额 2 位 |

## 5. 核算与报告

| 概念 | 表.列 | 谁写 | 谁读 | 口径 | 真相源 |
|---|---|---|---|---|---|
| 核算期 | `accounting_period.period` | 新建（选月） | 列表、报告、锁定 | `YYYY-MM`；每企业唯一 | `accounting_period.period` |
| 核算状态 | `accounting_period.status` | 计算/提交/复核/批准/锁定/解锁 | 列表、操作列、报告 | `draft → calculated → submitted → reviewed → approved → locked`；解锁回 `draft` | `accounting_period.status` |
| 范围一排放 | `accounting_period.scope1` | 计算（重算） | 列表、报告、首页 | 当期 `calc_version` 下 `scope_type=1` 的明细合计 | `accounting_line.emission`（按版本求和） |
| 范围二排放 | `accounting_period.scope2` | 计算（重算） | 列表、报告、首页 | 当期 `calc_version` 下 `scope_type=2` 的明细合计 | `accounting_line.emission`（按版本求和） |
| 排放总量 | `accounting_period.total` | 计算（重算） | 列表、报告、首页 KPI | **快照**：`scope1 + scope2`，由明细单向回填，禁止反写 | `accounting_line.emission` 求和 |
| 计算版本 | `accounting_period.calc_version` | 每次计算 +1 | 明细查询、报告 | 只增不减；历史明细保留，不覆盖 | `accounting_period.calc_version` |
| 明细排放 | `accounting_line.emission` | 计算 | 明细弹窗、报告 | `activity × factor_value`，保留 6 位 | `accounting_line.emission` |
| 因子快照 | `accounting_line.factor_value` | 计算 | 明细、报告 | 计算时复制，后续改因子不影响历史 | `accounting_line.factor_value` |
| 编制/复核/批准人 | `accounting_period.submitted_by / reviewed_by / approved_by` | 对应动作 | 列表、审计 | 三者互斥（职责分离），重复返回 `SOD_VIOLATION`(409) | 各列 + `audit_log` |
| 解锁原因 | `period_unlock.reason` | 管理员解锁 | 审计、详情 | 必填；`requested_by/approved_by` 至少记录操作人 | `period_unlock.reason` |
| 报告类型 | `report.report_type` | 生成 | 报告页、历史 | `carbon / energy / footprint` | `report.report_type` |
| 报告归属期 | `report.period_id / period_label` | 生成 | 列表、下载 | `period_id` 指向核算期；`period_label` 为展示快照 | `report.period_id` |
| 报告指纹 | `report.sha256 / file_size` | 生成 | 下载校验、列表 | `sha256(content)`；`file_size = length(content)` | `report.content` |
| 报告内容 | `report.content` | 生成（PDF 字节 base64） | 下载 | 生成后不可改；删除为软删 | `report.content` |

## 6. 双字段与快照规则

| 双字段 | 关系 | 同步方式 | 门禁 |
|---|---|---|---|
| `accounting_period.total` ↔ `sum(accounting_line.emission)` | 快照=明细合计 | 计算同事务写入 | 差异 > 0.05 即 FAIL |
| `accounting_period.scope1+scope2` ↔ `total` | 派生=分项和 | 计算同事务写入 | 差异 > 0.05 即 FAIL |
| `accounting_line.emission` ↔ `activity × factor_value` | 派生 | 计算时写入 | 差异 > 0.0001 即 FAIL |
| `carbon_trade.amount` ↔ `qty × price` | 派生 | 新建时计算 | 差异 > 0.01 即 FAIL |
| `report.file_size` ↔ `length(content)` | 派生 | 生成时写入 | 不相等即 FAIL |
| `alert_record.metric_value` ↔ 触发时读数 | 快照 | 生成时复制，不回写 | 允许历史差异（业务快照） |
| `production_value.product_name` ↔ `product.name` | 快照 | 新建时回填 | 允许名称变更后的历史差异 |
| `carbon_trade.asset_name` ↔ `carbon_asset.name` | 快照 | 新建时回填 | 允许名称变更后的历史差异 |

**规则**：快照只能由真相源单向回填；页面与接口不得把快照当真相再反算。派生指标（使用率、剩余、占比）只在一处实现，前端只展示接口值。

## 7. 派生指标（前端不得自行计算）

| 指标 | 计算位置 | 口径 | 展示 |
|---|---|---|---|
| 配额使用率 | `BootstrapService` / 配额页接口 | `emission / quota.total_qty × 100`，保留 2 位；`total=0` 时为 0 | 首页 KPI、配额页 |
| 剩余配额 | 同上 | `total_qty - emission`，可为负 | 首页 KPI |
| 资产可用量 | `TradeService` | `carbon_asset.qty - 未冲销售出量`；不足返回 `INSUFFICIENT` | 交易表单、资产列表 |
| 报告数量 | `BootstrapService` | `count(report where disabled=0)` | 首页、报告历史 |
| 成员席位占用 | `UserService` / 月巡检 | `count(user_tenant where status='active')` | 平台租户列表、月巡检 |

## 9. 变更纪律

1. 改字段：先改本表 → 改迁移 → 改接口 → 改页面 → 重跑 `data-check.sh` 与 e2e。
2. 改枚举：本表 §8 一行 + 表单/筛选/表格/图表/报告五处同步。
3. 新增双字段：必须在本表 §6 登记关系与门禁，否则评审不通过。
4. 本表与 `platform/docs/architecture.md` 冲突时，以库表与本表为准，架构文档只描述结构。
