## 二、发现的缺陷

### D-22（P1，已修复）设施编辑会清空上级，且无法设置上级

**现象**
1. 设施列表的「上级设施」永远显示 `—`（`SERVER_PAGES` 映射把 `parent` 硬编码为 `—`）；
2. 编辑任一子设施后保存，`parentId` 被写成 `null`，原有上下级关系丢失；
3. 新增/编辑时选择的上级不生效（本地树对象缺 `dbId`，保存时 `parent.dbId` 为 undefined）。

**影响**：设施树形关系无法维护，且编辑其它字段会静默破坏已有层级。

**修复**：映射保留 `parentName/parentId`；`flatFacilities` 补 `dbId`；列表新增「上级设施」列；备注列显示真实值。

**回归**：编辑「机加工车间」显示上级「一号厂区」，保存后 `parentId` 仍为 1。

---

### D-23（P1，已修复）产品碳足迹报告页的日期/产品筛选无效

**现象**：选择产品或年份后点「查询」，图表与表格不变；产品下拉只影响「生成报告」。

**根因**：`loadReportLive` 只读取日期范围控件（`[data-rp]`），碳足迹报告用的是年份下拉与产品下拉，未被读取。

**修复**：年份下拉加 `id="r-year"`、产品下拉加 `id="r-product"`；查询时拼 `?year=&product=`；产品下拉增加「全部」；未选具体产品就生成报告时提示「请先选择要生成报告的产品」。

**回归**：产品筛选 5 → 1 行；年份 2025 → 0 行。

---

### D-24（P1，已修复）事件预警编辑不可用、启停不落库

**现象**
1. 编辑事件（改名称/类型）保存报错：`400 缺少必填参数：enabled`；
2. 「禁用/启用」按钮只改前端状态，刷新后复原；
3. 列表「事件编码」「备注」两列恒为空（后端无对应字段）。

**根因**：`PATCH /api/alert-events/{id}` 只接受 `?enabled` 参数；前端却提交 JSON 表单；启停按钮没有调用接口。

**修复**
- 后端：新增 `updateEvent` 接收 `EventReq`；启停改为 `POST /api/alert-events/{id}/toggle?enabled=`；
- 前端：编辑走 JSON PATCH，启停调用 toggle 接口并刷新；
- 移除无后端的「事件编码」列与字段，备注补入数据库并展示。

**回归**：编辑改名 + 备注落库并显示；启停按钮「禁用」→「启用」，API 状态同步。

## 三、交付收尾（按确认结论实施）

### D-32（P2，已实现）接口方法统一为 PUT

**背景**：`PATCH` 实际要求提交完整主体，与 HTTP 部分更新语义不符，第三方对接会踩坑。

**实施**：后端 20 个 `@PatchMapping` 全部改为 `@PutMapping`；前端 21 处调用、Java 测试 27 处、`functional-cases.py` 与 `e2e.sh` 同步改为 PUT；CORS 允许方法收敛为 `GET/POST/PUT/DELETE/OPTIONS`；`architecture.md`、`multi-tenancy.md` 的方法约定同步更新。

**回归**：`PUT /api/products/5` → 200；`PATCH /api/products/5` → 405 `METHOD_NOT_ALLOWED`；单测 100、功能用例 142、交互 37 全过。

### D-33（P2，已实现）报告列表改为分页

**背景**：`GET /api/reports` 返回裸数组，与其它列表接口的分页结构不一致。

**实施**：返回 `{total, rows, page, size}`，新增 `page`/`size` 参数（上限 200）；`e2e` 与功能用例的取数改为 `body.rows`。

**回归**：`?type=carbon&page=1&size=2` → `total=5, rows=2`。

### D-34（P3，已实现）分页上限统一为 200

审计日志与平台端两处上限由 100 调整为 200，全站分页上限一致。

### D-35（P2，已实现）草稿期禁止生成正式报告

**背景**：核算期间未提交也能生成报告，报告数据未经复核确认。

**实施**：`carbon` / `energy` 报告生成前校验期间状态，`draft`、`calculated` 均视为未提交，返回 `409 PERIOD_LOCKED`「核算期间尚未提交，请先提交后再生成正式报告」；`footprint` 报告按足迹记录生成，不受期间状态影响。

**回归**：未提交时生成 → 409；提交后生成 → 200。单测 `AccountingFlowTest`、`ExportTest`、`AnalysisReportTest` 与 `functional-cases.py`、`e2e.sh` 均已补充提交前置步骤。

### D-36（P1，已修复）三类报告 PDF 排版遮挡

**现象**：碳排放核算、能源利用、产品碳足迹三份导出 PDF 中，章节标题的下缘被紧随其后的表格上边框与浅绿表头压住，「二、核算明细」「一、能源消费」最明显；此外长中文设备名折行后第二行会溢出单元格。

**根因（三处叠加）**：

1. 章节标题段落与其后表格的间距为 0。`Paragraph` 的高度按 1.4~1.5 倍行距计算，字形绘制在行框下缘，表格顶边紧贴段落底边，边框正好落在字形上。实测标题文字底边与表格首行文字顶部仅 5.6pt。
2. 单元格内容用 `Phrase` 承载，在 CJK 字体下换行高度只按单行计算，中文长文本折成两行时单元格高度不增长，第二行溢出到边框外。
3. 机器可读摘要行强制 `HELVETICA`，`boundary=摇篮到大门` 的中文被静默丢弃，输出成 `boundary= unit=t`。

**修复**：

- 新增 `title()` / `section()` / `body()` / `footer()` / `machine()` 五个段落骨架方法，章节标题带 `spacingBefore=12`、`spacingAfter=2`；
- 新增 `table()` 表格工厂：`spacingBefore=7`、`spacingAfter=8`、`headerRows=1`（跨页重复表头）、`splitLate=false`；
- 单元格统一走 `cell()`：内容用 `Paragraph`、在 `PdfPCell` 上显式 `setLeading(size×1.35)`（`PdfPCell` 会忽略段落自身 leading，不设则行距塌陷为字号大小）；
- 数值列（含负数、小数、百分比）自动右对齐，文本列保持左对齐；
- 机器可读摘要的中文枚举转固定 ASCII 代码（`CRADLE_TO_GATE` / `CRADLE_TO_GRAVE` / `t` / `kg` 等），未知值回退 `UNKNOWN`；
- 碳排放明细表「设备」列由 2.2 加宽至 3.0，减少长设备名折行。

**回归**：标题与表格间隙由 5.6pt 提升至 14.6pt；60 行超长设备名跨 3 页，每页重复表头、无行被拆断；新增 `PdfLayoutTest` 3 条（标题不被压、折行行高递增、机器行 ASCII 完整），单测 100 → 103。
