# 问题库（M20）

> 每条：现象 → 根因 → 规则 → 对应门禁。新项目启动先当检查表过一遍；同类问题复发时回到对应复盘。
> 来源：本项目真实事故/未遂，复盘见 `docs/retrospectives/`。

| # | 现象 | 根因 | 规则 | 门禁 / 证据 |
|---|---|---|---|---|
| P01 | 旧 Cookie 用户打开登录页，登录接口也返回 401，永远登不回来 | 过滤器把认证入口当受保护接口，无匿名白名单 | R11：认证入口显式匿名；过滤器只处理 `/api/**` | e2e“旧会话 Cookie 下仍可重新登录”；`JwtAuthFilter.ANONYMOUS` |
| P02 | 清理测试数据时，平台管理员 `13900000000` 被测试号段前缀匹配，差点删除 | 用手机号前缀当唯一身份，未列保护名单 | R14：删除脚本默认预演 + 排除平台/演示账号 | `purge-test-data.sh` 预演计数；平台账号登录 200 |
| P03 | 启动时 Flyway 执行已删除的 V99，与 V100 撞列，服务起不来 | `mvn package` 未 clean，target 残留旧迁移 | R12：发布必须 clean package | 发布第 14 项：源码迁移数 = jar 内迁移数 |
| P04 | e2e 跑多次后库里有 48 个测试账号、12 个测试租户、25 个测试产品 | 清理只删成员关系；软删保留行；无残留断言 | R13：`TST-` + trap + 残留断言 0 | e2e 结束“测试数据残留 0”；`data-check` 唯一性 5 项 |
| P05 | 备份恢复后只有 29 张表、报告为空，中文乱码 | mysqldump 缺 `--default-character-set=utf8mb4 --hex-blob` | 备份脚本固定字符集与 hex；恢复后做表数/行数对账 | `backup.sh`；恢复演练 35 表一致 |
| P06 | 外部协作者能打开报告列表但下载 401/403 未生效 | 下载接口返回 `ResponseEntity<byte[]>`，外部授权切面未覆盖 | 下载方法首行显式 `external.assertAllowed`；授权用例覆盖下载 | e2e“外部账号可下载已授权报告” |
| P07 | 报告页图表/阶段表、首页年份、读数默认时间都是写死演示值 | 原型期用静态数据撑页面，转正时未清理 | 页面不写业务数据；时间由当前时间或后端字段推导 | `gate-l0` F11；全仓无 `2026-11` 硬编码 |
| P08 | `/api/bootstrap` 膨胀到 400KB，首页拖慢 | 14 个台账全量塞进快照 | 快照只留字典/KPI/聚合；台账走服务端分页 | `perf.sh` bootstrap ≤ 60KB；`BootstrapTest` 断言键不存在 |
| P09 | 解锁核算期后状态回 `draft`，用户以为还能直接提交 | 状态机语义：解锁 = 作废本次计算，需重算 | 文档写明；解锁弹窗提示“需重新计算” | `state-machines.md`；`AccountingFlowTest` |
| P10 | 前端双击“保存”生成两条相同记录 | 创建接口无幂等，双击发两次 | POST 创建带 `Idempotency-Key`；前端 5s 复用键 | `IdempotencyTest` 3 条；`IdempotencyFilter` |
| P11 | 同一份事实在 4 份文档里数字不一致（断言数、路由数、接口数） | 数字散落各文档，无单一维护点 | 数字只在一处维护，其余引用；一致性脚本检查 | `tools/check-docs.sh`（禁用过期数字/旧口径） |
| P12 | 演示账号与固定验证码常显在登录页，等于公开管理员密码 | 原型期方便评审，转正未摘 | 登录页不出现任何账号/验证码提示 | `check-ui` U00；`gate-l0` F11 |

## 使用方式

1. 新项目第 1 天：逐条对照，凡命中的先补规则再开工。
2. 每次复盘：至少新增或更新一条；没有新增说明复盘不充分。
3. 规则与门禁必须能指到文件/命令；只有“注意一下”的条目不收录。
