# 协作协议（M19）

> 适用：多人/多智能体并行、任务会话与打包会话分离。1 人项目也保留「交接四元组」与「写作用域」。
> 原则：**边界先于速度**——先说改哪里、依赖谁、怎么验，再动手。

## 1. 席位与职责

| 席位 | 职责 | 不得 |
|---|---|---|
| H1（用户/决策人） | D2/D3 决策、验收、范围签字 | 不直接改代码 |
| A0（主控/汇总） | 任务拆分、依赖排序、唯一打包、最终验收 | 不跳过门禁 |
| A1…（任务会话） | 在 `write_scopes` 内实现与自检 | 不跨域改文件、不打包 |
| Critic（轮值） | 找“为什么没拦住/没测出/流程允许” | 不作为本次改动 owner |
| Facilitator（轮值） | 复盘时间盒与追问 | 不为被复盘事项的直接 owner |

## 2. 任务板四要素

每个任务开卡必须写全，缺一项不排期：

```yaml
task_id: T-20261125-01
owner: A1
deliverable: "改了哪些文件、产出什么"
write_scopes:
  - platform/backend/src/main/java/com/carbonbal/auth/
  - platform/backend/tools/
acceptance: "可复跑命令 + 期望输出"
blocked_by: [T-20261125-00]   # 显式依赖，不靠口头
pack_session: false            # 只有 A0 的汇总会话可为 true
```

规则：

1. **写作用域**：只改 `write_scopes` 内文件；需要越界先改卡、通知 A0。
2. **依赖显式**：`blocked_by` 未清空不认领；认领即承诺交付「文件 + 自检结果」。
3. **验收可跑**：写命令与期望输出，不写“正常/完整”。
4. **打包唯一**：只有 A0 汇总会话打包；任务会话只交“改动 + 验证 + 待打包说明”。

## 3. 交接四元组（每次交付结尾）

| 项 | 内容 | 不合格示例 |
|---|---|---|
| artifact | 改动文件路径（必要时行号） | “改好了” |
| decision | ≤3 条关键决定与理由 | 只贴截图 |
| assumptions | 假设与待确认项，标“什么证据会推翻” | 静默假设 |
| next | 1–3 条后续/阻塞 | “没了” |

本项目在四元组上增加 `verification`（验证命令与结果），合称**交接五件套**，见 `AGENTS.md` §3.2。

## 4. 冲突仲裁

| 冲突 | 以谁为准 | 处理 |
|---|---|---|
| 同文件并行改 | 先到者 | 后到者停，提 issue 给 owner，不覆盖 |
| 字段/口径 | `carbonbal-web/docs/字段与口径.md` | 改口径先改文档，再改代码 |
| 接口 | `platform/docs/architecture.md` §4 + `error-codes.md` | 契约先行，前端不猜字段 |
| 视觉 | `assets/app.css` token | 做不到的登记“受限项”，不硬编码 |
| 状态/权限 | `state-machines.md` / `permissions.md` | 服务层集中迁移，页面不改状态 |

## 5. 版本与打包

- 版本只向上递增，禁止覆盖旧包；旧包归档保留。
- 打包前：`sync-frontend.sh --check` 一致、`mvn clean package`、14 项发布验证。
- 打包后：`release-and-rollback.md` §6 台账登记版本/字节/SHA256/门禁/Flyway。
- 回滚：整包回退；数据库以备份恢复为准，不执行 down 迁移。

## 6. 协作检查表（开工前 60 秒）

- [ ] 任务卡四要素齐全，`write_scopes` 不与在跑任务重叠
- [ ] `blocked_by` 为空
- [ ] 验收命令能直接复制执行
- [ ] 知道本次改动属于 D0/D1/D2/D3 哪一级
- [ ] 知道交付时要给哪五件套
