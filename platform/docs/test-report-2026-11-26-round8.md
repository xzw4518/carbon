## 三、发现的问题

### T-1（P2，已修复）性能门禁自图形验证码上线后一直登录失败，14 项预算实际未执行

- **复现**：`bash tools/perf.sh` → `[FAIL] 登录失败，无法采样`，退出码 1。
- **根因**：密码登录在第七轮之前的改造中强制了图形验证码，`e2e.sh`、`functional-cases.py`、Java/Node 四处都改了，**`perf.sh` 漏改**，仍以裸 `{phone,password}` 登录。
- **影响**：性能预算（首屏 FCP/LCP、接口 P95、bootstrap 体积、DOM 节点等 14 项）在此前若干轮里都没有真正跑过，属于“门禁绿灯假象”。
- **修复**：脚本先 `GET /api/auth/captcha`，用 Python 从 SVG 里解析字符，再带 `captchaId/captchaCode` 登录。
- **回归**：修复后 **14/14 达标**（overview 28ms、bootstrap 3KB gzip、FCP 356ms、LCP 356ms、首屏 10 请求 40KB、控制台 0 错误）。

### T-2（P3，已修复）上传文件名未清洗，`../evil.csv` 原样入库并写进下载头

- **复现**：`POST /api/files` 上传文件名为 `../evil.csv` → 200，返回 `name="../evil.csv"`；下载时 `Content-Disposition` 也带该名。
- **影响**：磁盘落盘用的是 `UUID.ext`，**不存在目录穿越写入**；但文件名会出现在附件列表与下载头，旧客户端/脚本可能据此写到上级目录，也便于伪装扩展名。
- **修复**：`FileService` 增加 `sanitizeName()` —— 只取 basename、去控制字符、去前导点、限长 200（保留扩展名）。
- **回归**：`../evil.csv`→`evil.csv`；`..\..\win.ini`→`win.ini`；`...hidden.txt`→`hidden.txt`；260 字符名截断且保留 `.pdf`；`正常 文件名 2026.pdf` 原样保留。

### O-1（P3，已修复）导入缺列的行按默认值补齐，且不告警

- **复现**：产品导入只填前两列（`编码,名称`），其余列留空 → `success=1`，落库后 `产品类型=一般产品`、`产品分类=工业产品`、`单位=吨`。
- **影响**：从 Excel 截断的 CSV 会“看起来导入成功”，但分类/单位被静默补默认值，后续统计口径可能不对。
- **修复**：`ImportService.loop()` 取表头列数，逐行比对——少列记 `warnings`「该行只有 X 列（模板 Y 列），缺少的字段已按默认值补齐」；多列记「列数不一致，请检查多余逗号或引号」；成功计数不变。同时把逐行错误从中文化：数值 `数值格式不正确：abc`、日期 `碳足迹日期格式不正确：2026-13-45（应为 yyyy-MM-dd）`、整数 `年度必须是整数：abc`（此前会回显 Java 内部英文异常）。
- **回归**：缺列 → `success=1` + 1 条告警（行号 2）；完整列 → 无告警；多列 → 告警 + 该行失败；供应商未知上级告警与新列告警可合并返回。前端 toast 显示「N 条告警（明细见控制台）」，上级未匹配场景仍显示专用文案。

### O-2（测试卫生）探索测试会留下 TST 产品

- 本轮探索产生的 8 条 `TST-*` 产品已由 `reset-demo.sh`（ui-flows 收尾自动调用）的 purge 清理，当前库内 `TST` 产品为 0。后续探索脚本建议同样以 `TST ` 命名并复用 `purge-test-data.sh`。

### 已知限制（复核确认，非新缺陷）

- viewer 仍可绕过 UI 直接调写接口（`POST /api/products` → 200）；`HANDOVER.md` §8 已写明权限模型边界。
