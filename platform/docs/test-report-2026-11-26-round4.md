## 三、发现的问题

### D-11（P1，已修复）碳足迹核算：编辑弹窗「核算边界」是只读输入框，无法修改

**复现**
1. 进入「碳足迹管理 → 碳足迹核算」
2. 点击任一产品的「编辑」
3. 「核算边界」渲染为 `<input readonly>`，既不是下拉，也没有 `name` 属性

**影响**：字段不可编辑；且保存时 `FormData` 取不到值，回落到原值，用户以为改了实际没改。与新增弹窗（下拉：摇篮到大门 / 摇篮到坟墓）不一致。

**根因**：编辑弹窗模板把 boundary 写成了只读输入框，且缺 `name`。

**修复**：改为 `select`，选项与新增一致，默认选中当前值；保存时正常取值。已同步 `自研原型` 与后端 `static/app` 两份资源。

**回归**：真实浏览器 — 下拉显示 2 个选项、当前值正确；改为「摇篮到坟墓」保存后 API 回读为新值；数据已还原。

---

### D-12（P1，已修复）碳足迹编辑保存会把原核算日期改成「该年 1 月 1 日」

**复现**
1. 取一条 `2026-11-12` 的足迹记录，点「编辑」
2. 不做任何修改，直接「保存」
3. 详情/列表中日期变为 `2026-01-01`

**影响**：静默改写业务日期，月度归属、分析口径、审计追溯全部失真；用户完全无感知。

**根因**：保存时 `date = 年度 + '-01-01'`，年度下拉只有年份，丢掉了原月日。

**修复**：保留原日期的月日部分，仅在切换年度时替换年份：`(d.year || 原年) + 原日期.slice(4)`。

**回归**：同一记录编辑保存后日期仍为 `2026-11-12`，边界与日期均正确还原（version 递增正常）。

---

### D-13（P1，已修复）碳足迹分析页筛选条件完全无效

**复现**
1. 进入「碳足迹管理 → 碳足迹分析」
2. 「产品名称」选任一产品，「日期」选 2025，点「查询」
3. 表格、KPI、图表全部不变

**影响**：页面提供了筛选能力但结果不响应，用户无法按产品/年度定位足迹热点。

**根因**（两层）
- 前端 `analysisPage` 的 `queryString()` 只拼接 `monthRange` 的 `from/to`，`select` / `year` 类型的值从未进入请求；
- 两个筛选项未配置 `key`，控件值也没写入 `st.filters`。

**修复**
- `queryString()` 增加通用参数拼接：按筛选项 `key`/`param` 输出，支持 `toParam` 映射；
- 筛选项补 `key`（年份 → `year`，产品 → `product`），后端 `/api/analysis/footprint` 增加 `product` 参数（按名称精确过滤，兼容原有 `productId`）。

**回归**：产品筛选 5 → 1 行；年份 2025 → 0 行；2026 → 5 行。

### D-14（P1，已修复）供应链碳管理分析筛选条件完全无效

**复现**
1. 进入「碳足迹管理 → 供应链碳管理分析」
2. 选供应商、选年份后查询，数据不变

**影响**：同上，筛选形同虚设。

**根因**：后端 `/api/analysis/supply-chain` 不接收任何参数，前端即使传了也会被忽略。

**修复**：后端增加 `supplier`（名称精确）与 `year`（按核算日期年份区间）参数；前端筛选项补 `key`/`param`，复用修正后的 `queryString()`。

**回归**：供应商筛选 4 → 1 行；年份 2025 → 0 行；2026 → 4 行。

### D-15（P2，已修复）碳配额 / 信用资产导出含页面不存在的「到期日」列

**复现**
1. 「碳资产管理 → 碳配额资产管理」点「导出」
2. CSV/Excel 表头为：资产名称、类型、数量、单位、年度、状态、**到期日**
3. 页面列表与新增/编辑表单均无「到期日」字段，表单也不可维护该值

**影响**：导出与页面字段不一致，且该列恒为空，甲方对账时会被质疑数据来源。

**修复**：两处导出（`carbon-assets`、`credit-assets`）删除「到期日」列，表头收敛为：资产名称、类型、数量、单位、年度、状态。

**回归**：下载实文件校验，表头无「到期日」；页面列与导出列语义对齐。

### D-16（P2，已修复）筛选无匹配时返回 404，页面显示「数据加载失败」而非「0 条」

**复现**：碳足迹分析选 2025（无数据），页面顶部出现黄色错误横幅「数据加载失败：暂无产品足迹数据」。

**影响**：把「筛选无结果」误报成系统错误，用户会以为页面坏了。

**修复**：足迹 / 供应链分析在**带筛选参数**且结果为空时返回 200 + 空视图（KPI、图表、表格均为空）；不带任何筛选且库中无数据时仍返回 404，保留原语义。

**回归**：`AnalysisFilterTest` 4 条覆盖（年份命中/未命中、产品命中/未命中、供应商、无非筛选参数）；原 `AnalysisReportTest` 中 `productId=99999` 断言由 404 调整为 200 + 空行。

### D-17（P2，待确认）碳足迹「备注」输入框不落库

新增与编辑弹窗都有「备注」输入框，但后端实体 `product_footprint` 与 `FootprintDtos.Req` 都没有 `remark` 字段，提交后被丢弃。用户填写后备注消失。

**建议**：要么删除该输入框（诚实），要么加字段 + Flyway 迁移（`V110__add_footprint_remark.sql`）并补导出。需产品确认，未擅自改表结构。

### D-18（P2，设计待确认）没有真正的「只读」角色，普通成员可直接调用写接口

实测：`13800000003`（查看者）调用 `POST /api/products` 返回 200 并成功创建。原因是接口鉴权只到 `hasAnyRole('ADMIN','USER')`，所有租户成员 `role` 都是 `user`；「查看者」只是角色页面集合较小，而当前该角色恰好拥有全部 34 个页面。

**说明**：这与「角色 = 页面集合」的现有模型自洽（页面权限不区分读写），前端会按 `canWrite/isAdmin` 隐藏按钮，但 API 层不拦。若产品需要「只读成员」，需要在页面权限之外增加操作维度（view/edit），属于权限模型变更，未在本次范围内改动。

---

### D-19（P3，建议）静态资源全部 `no-store`，每次访问重新下载约 460KB

`/app/index.html` 与 `assets/*` 均返回 `Cache-Control: no-cache, no-store, must-revalidate`（Spring Security 默认）。好处是改版立即生效；代价是首屏每次都重下资源（gzip 后约 130KB）。

**建议**：`index.html` 保持 no-store；`assets/*` 加内容指纹（`?v=<hash>`）+ `max-age=31536000, immutable`。收益是回头客首屏显著加快，风险是发版需同步改引用。

---

### D-20（P3，建议）PATCH 实为全量替换，不符合部分更新语义

实测 `PATCH /api/products/{id}` 仅传 `name` 返回 400（`code/type/cls/unit` 均标 `@NotBlank`）。前端目前总是提交全量，功能可用，但第三方集成按 PATCH 语义只传变更字段会失败。

**建议**：要么把接口改为 `PUT`（诚实表达全量），要么为 PATCH 定义独立的可选字段 DTO 并做空值保留。

## 六、补充测试建议

1. **筛选回归纳入门禁**：在 `ui-flows.cjs` 增加两条——「足迹编辑边界为下拉且保存生效」「分析页选产品后行数下降」，防止同类问题复发。当前 37 条门禁未覆盖筛选。
2. **导出列与页面列的一致性检查**：写一个脚本对 15 类导出逐页比对「页面表头 ⊇ 导出表头」，把「导出多出页面没有的列」作为断言。本轮已发现 1 类（到期日），其余差异多为同义不同名（数量/资产数量、月份/日期），建议先统一词表再上断言。
3. **日期字段编辑专项**：凡「按年度选择 + 展示具体日期」的表单（足迹、产值、节能改造）都应验证「只改其他字段时日期不被改写」。建议补一条跨页面参数化用例。
4. **空结果语义统一**：8 个分析接口目前「无数据」都抛 404，建议统一为「无筛选参数 → 404，有筛选参数 → 200 空视图」，并补接口测试。
5. **权限模型补测**：若确定引入只读角色，需要补「view 角色调用 POST/PATCH/DELETE 全部 403」的矩阵用例（当前只有 DELETE 受限）。
6. **并发写幂等**：本轮只做了单线程幂等（O01–O03），建议补「同 Idempotency-Key 并发 5 请求只落一条」。
7. **附件上传边界**：补超大文件（>10MB）、可执行文件类型、文件名注入（`Content-Disposition`）三类用例。
