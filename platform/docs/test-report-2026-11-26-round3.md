## 二、发现的问题

### D-08（P1，已修复）外部协作者声称拥有全部 34 个业务页面，与实际权限冲突

**复现**
1. 管理员建外部账号：`POST /api/users {kind:"external", role:"viewer"}`
2. 该账号登录后 `GET /api/auth/me` → `pages` 返回 34 个页面编码（含 `product.list`、`report.carbon`）
3. 实际访问 `GET /api/products` → `403 EXTERNAL_LIMITED`；`GET /api/bootstrap` → 403

**影响**：前端路由守卫按 `pages` 判断，直接输入 `#/carbon-product/product/list` 会放行并渲染页面，随后所有接口 403，页面变成一堆错误；菜单虽被 `kind=external` 特判隐藏，但权限模型自相矛盾。

**修复**：外部协作者的令牌与 `me` 响应 `pages` 一律为空；`JwtAuthFilter` 对 `kind=external` 跳过页面校验，继续按 `externalAllowed` 的 URL 白名单（门户、授权报告/附件下载、期间详情）放行。浏览器实测：登录落 `#/external/portal`，菜单只有「我的授权」，直输业务路由显示“没有该功能的访问权限”，控制台 0 错误。

### D-09（P2，已修复）CSV 导出存在公式注入

**复现**
1. 新建产品，名称填 `=1+1`
2. `GET /api/export?resource=products` → 导出行首单元格为 `=1+1`（未转义）
3. 用 Excel 打开会作为公式执行；`@cmd`、`+SUM(...)` 同理

**修复**：`Csv.escape` 对以 `= + - @ Tab CR` 开头的单元格加单引号前缀强制文本；纯数字（含负数、科学计数）保持原样，避免把 `-1.5` 变成文本。新增 `CsvTest` 3 条（公式中和、负数不变、逗号引号转义）。

### D-10（P2，已修复）清理脚本漏掉演示租户内的测试数据

**现象**：`purge-test-data.sh` 只按租户/TST 名称清产品、设备、设施等，但演示租户内由用例创建的 TST 供应商（8 条）、TST 碳资产（8 条）和端到端软删的产值（40 条）长期残留，`data-check` 也不报。

**修复**：清理脚本增加供应商、碳资产（先删关联交易）按名称清理，并纳入残留统计；已一次性清零。软删产值属 e2e 每次“建了再删”的固有产物，本轮手工清理，后续建议 e2e 用独立测试租户或增加硬删入口。
