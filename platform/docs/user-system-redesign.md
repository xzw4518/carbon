# 用户体系重构产品方案（v2 · 2026-11-25）

> 定位：多租户 SaaS。本文是**目标产品模型**，不以现有实现为约束；现有代码只作为迁移输入。
> 核心变化：从“5 个固定角色 + 平台运营”改为 **三级用户 + 租户内角色可配置 + 租户授权期硬控制**。

**配套文件**

- 页面原型：`../../carbonbal-web/prototypes/user-system-v2.html`（浏览器直接打开，含租户/用户/角色三页与关键交互）
- 接口清单：`user-system-api.md`（数据模型、权限点、接口契约、错误码、验收点）

## 1. 一句话结论

平台只有两类人：**管平台的**和**用平台的**。
- 管平台的叫**超级管理员**，是平台最高权限：管租户与授权，也能进入任意租户查看和管理全部数据；
- 用平台的按租户隔离，每个租户有**租户管理员**（本租户超管）和**普通用户**（权限由角色决定）；
- 角色是租户自己的资产，可增删改查，但只配置**能进入哪些功能页面**，碰不到系统管理；
- 租户有授权期，到期当天起**该租户所有账号禁止登录**（超级管理员仍可从平台进入排障），续期即恢复。

## 2. 设计原则

1. **层级与角色正交**：三级用户是“身份层级”，角色是“业务权限包”。普通用户才有角色；租户管理员天然拥有本租户全部业务权限；超级管理员可进入任意租户，进入后以该租户上下文操作，便于追溯。
2. **系统管理不下放**：用户管理、角色管理、租户信息、审计日志只属于租户管理员与超级管理员，不进入角色页面目录，避免“配着配着把自己锁死”。
3. **页面只做加法**：角色勾选的是“可进入的页面”，默认无页面，勾选才有。
4. **职责分离是业务规则**：核算的编制/复核/批准按人校验，不写进角色；角色只决定能否进入核算页面。
5. **到期即阻断**：授权到期不是提醒，是硬停；数据保留，续期即恢复。
6. **超级管理员不受任何限制**：可进入任意租户查看与管理全部业务、用户与角色；不受角色权限、职责分离、租户状态约束。系统只做操作留痕用于追溯，不拦截、不阻断。

## 3. 三级用户模型

| 层级 | 名称 | 归属 | 账号来源 | 能做什么 | 不能做什么 |
|---|---|---|---|---|---|
| L1 | **超级管理员** | 平台 | 平台初始化/运维开通 | 租户开通、续期、停用、套餐与席位、平台概览；可进入任意租户查看与管理全部业务、用户、角色；**不受任何业务规则限制** | 无（平台最高权限） |
| L2 | **租户管理员** | 某租户 | 开通租户时指定，或由现任租户管理员新增 | 本租户全部业务 + 用户管理 + 角色管理 + 租户信息 + 审计 | 不能跨租户；不能给自己续期；不能删除最后一名租户管理员 |
| L3 | **普通用户** | 某租户 | 租户管理员新增 | 由角色决定：能进入哪些功能页面 | 不能进系统管理；不能跨租户 |

补充规则：

- 一个手机号可以属于多个租户（一个账号、多条成员关系），登录后选租户；某个租户到期不影响其他租户。
- 超级管理员账号**不允许**同时是任何租户的成员，避免权限混淆。
- 超级管理员进入租户采用**显式上下文**：顶部横幅提示“正在访问 XX 租户”，可随时退出回平台；操作留痕用于追溯，不做拦截。
- 超级管理员**不受角色权限、职责分离、租户状态限制**：到期/停用的租户也能进入并操作；同一期间可一人完成编制、复核、批准。
- 租户管理员可以有多个，但至少保留一个；自己不能停用/降级/删除自己。

## 4. 角色模型（简化版）

> 本期角色只回答一个问题：**这个角色能进入哪些功能页面**。
> 不做动作级权限、不做数据范围、不区分内置/自定义。

### 4.1 角色是什么

- 角色 = 名称 + 说明 + 一组页面编码；
- 普通用户必须绑定且只能绑定一个角色；租户管理员不绑定角色；
- 新租户开通时自动创建一个默认角色【运营】，默认拥有全部 34 个业务页面（不含系统管理）；
- 角色可增删改查；至少保留一个角色，删除最后一个返回 409；
- 每租户角色数 ≤ 30。

### 4.2 页面目录

角色勾选的是“功能页面”，按菜单分组：

| 分组 | 页面数 | 示例 |
|---|---|---|
| 首页 | 1 | 首页 |
| 企业管理 | 2 | 企业信息、集团汇总 |
| 预算管理 | 1 | 碳排放配额 |
| 产值管理 | 3 | 产品列表、产品产值、生产总值 |
| 碳排放核算 | 1 | 碳排放核算 |
| 碳足迹管理 | 4 | 碳足迹核算、碳足迹分析、供应链碳管理、供应链分析 |
| 碳资产管理 | 3 | 碳配额资产、信用资产、交易管理 |
| 碳核查支撑 | 2 | 原始凭证、第三方报告 |
| 报告查询 | 3 | 碳排放报告、能源利用报告、产品碳足迹报告 |
| 能碳分析 | 6 | 能耗查询、策略推荐、能效对标、碳排放查询、碳配额核算、能流分析 |
| 设备设施 | 3 | 设施管理、设备管理、设备数据 |
| 预警管理 | 3 | 事件预警、预警设置、预警记录 |
| 节能管理 | 2 | 节能改造、能源管理情况 |

合计 34 个业务页面。系统管理（用户/角色/租户信息/审计）不在此目录，只属于租户管理员与超级管理员。

### 4.3 页面权限怎么生效

- 前端：`/auth/me` 返回 `pages[]`，菜单与路由只渲染有权限的页面；直接访问未授权路由显示 403。
- 后端：每个业务接口声明所属 `page_code`；请求校验用户 `pages` 是否包含该页面。**不能只藏菜单不拦接口。**
- `/api/bootstrap` 只返回用户有权限页面的数据，避免快照泄露。
- 租户管理员与超级管理员跳过页面校验（超级管理员无任何限制）。

### 4.4 动作权限本期不做

- 页面内的新增、编辑、删除、导出、计算、复核、批准，本期**不做角色级控制**：能进入页面即可按业务状态操作。
- 职责分离仍是**业务规则**，不是角色配置：
  1. 同一期间，编制人 ≠ 复核人；
  2. 同一期间，复核人 ≠ 批准人；
  3. 违反返回 409 `SOD_VIOLATION`；
  4. 租户管理员同样受此约束；
  5. **超级管理员不受此约束**，可一人完成编制、复核、批准。
- 后续如需要“只读角色/审批角色”，再在角色上增加动作位；本期不预留矩阵 UI。

### 4.5 角色管理页面

列表：角色名、用户数、可进入页面数、更新时间、操作。
操作：新建、编辑、删除、查看用户。

新建/编辑弹窗：

1. 基本信息：名称（租户内唯一）、说明；
2. 页面树：13 个分组，分组可全选，页面逐个勾选；顶部显示“已选 X / 34”；
3. 不出现动作列、数据范围、类型标签。

删除规则：有用户的角色不可直接删（提示人数，先转移）；最后一个角色不可删；删除记审计。

## 5. 租户与授权期

### 5.1 租户字段

| 字段 | 说明 |
|---|---|
| 名称 / 编码 | 编码全局唯一，用于登录后识别 |
| 状态 | `pending`（未生效）/ `active` / `suspended`（人工停用）/ `expired`（授权到期） |
| 授权开始 / 到期 | 日期；到期当天 23:59:59 后失效 |
| 套餐 / 席位上上限 | 席位数按“启用中的普通用户 + 租户管理员”计 |
| 租户管理员 | 至少一名，开通时指定 |
| 备注 / 创建人 / 操作记录 | 审计 |

### 5.2 状态与行为

| 状态 | 登录 | 已登录会话 | 数据 |
|---|---|---|---|
| pending | 拒绝（未生效） | — | 已建、不可用 |
| active | 允许 | 正常 | 正常 |
| suspended | 拒绝（已停用） | 立即失效 | 保留 |
| expired | 拒绝（授权到期） | 立即失效 | 保留，续期恢复 |

- 到期/停用只阻断**该租户的账号**；超级管理员不受租户状态限制，可进入并操作该租户，进入时横幅提示“该租户已到期/已停用”。
- **无宽限期**：到期即阻断，不做“只读 N 天”的过渡。
- 到期判定：每天 00:05 定时任务把 `expire_at < 今天` 的租户置为 `expired`，并把该租户所有账号的会话版本 +1（强制下线）。
- 登录与每次请求双重校验：不能只靠定时任务，接口层也要看租户状态与到期时间（缓存 30 秒）。
- 续期：超级管理员改到期日 → 状态回 `active` → 用户可重新登录；**不补数据、不清权限**。
- 停用/续期/到期都必须写平台审计，记录操作人、时间、前后值。

### 5.3 到期提醒

- 到期前 30 / 7 / 1 天，平台概览与租户列表标黄；
- 租户管理员登录后首页顶部提示“授权将于 X 天后到期，请联系平台续期”；
- 提醒只做站内，不依赖短信/邮件（客户环境职责）。

### 5.4 租户管理页面

**列表**：名称、编码、状态、授权起止、剩余天数、席位使用、租户管理员、操作。
筛选：状态、到期区间、关键词。
操作：开通、续期、停用、恢复、查看详情。

**开通向导**（四步）：

1. 企业信息：名称、编码、行业、规模；
2. 管理员：手机号、姓名（系统创建账号并返回初始密码）；
3. 授权：开始日期、到期日期、套餐、席位上限；
4. 确认：摘要 + 提交，生成租户、默认角色【运营】、默认设施。

**详情页**：基本信息、授权卡片（剩余天数/续期按钮）、席位使用、用户统计、操作记录。

## 6. 功能模块与菜单

```
平台管理（仅超级管理员）
├─ 平台概览        租户总数/活跃/到期/30 日内到期/席位使用
├─ 租户管理        列表、开通、详情、续期、停用、**进入租户**
└─ 平台审计        跨租户的开通/续期/停用/代管操作

系统管理（租户管理员；超级管理员进入租户后同样可见）
├─ 用户管理        列表、新增、改角色、重置密码、启停、解锁、交接、删除
├─ 角色管理        列表、新建、页面勾选、删除、查看用户
├─ 租户信息        名称/编码/授权起止/剩余天数（租户管理员只读）
└─ 审计日志        操作人、模块、动作、对象、时间、前后值

业务菜单（按角色权限显示；超级管理员全量可见）
└─ 13 个业务模块，无权限则不显示菜单，直接访问路由返回 403
```

登录后落地页：

- 超级管理员 → 平台概览；
- 租户管理员 → 首页；
- 普通用户 → 第一个有查看权限的模块；一个都没有则显示“暂无权限，请联系管理员”。

## 7. 关键流程

### 7.1 开通租户

超级管理员填四步 → 系统创建：租户（pending/active 按开始日期）→ 默认角色【运营】（34 个业务页面）→ 租户管理员账号 → 默认设施 → 平台审计。
返回：租户编码、管理员初始密码（一次性）。

### 7.2 登录

手机号+密码（短信作为可选通道）→ 校验账号状态 → 查成员关系 →
逐个租户校验：状态 active 且在授权期内 → 过滤不可用租户 →
无可用户 → 提示（到期/停用/未生效，给出具体原因）→
单租户直接进，多租户选择 → 签发令牌（含租户、层级、权限版本）→ 加载权限。
超级管理员默认进入平台上下文；选择“进入租户”后切换为租户上下文，退出恢复平台上下文。

### 7.3 角色变更

租户管理员改页面集合 → 保存 → 角色版本 +1 →
该角色下所有用户权限版本失效 → 下次请求重新加载（≤30 秒）→ 审计。

### 7.4 租户到期

每天 00:05 → 扫描到期租户 → 状态置 expired → 该租户所有账号会话版本 +1 →
登录返回“授权已到期，请联系平台续期” → 接口返回 423 → 数据保留。

### 7.5 用户离职

交接（把创建人/负责人转给他人）→ 停用或删除成员关系 → 会话立即失效 → 审计。
账号本身保留（手机号可重新邀请），不物理删除历史审计。

## 8. 规则清单（验收用）

1. 超级管理员可看可管所有租户，不受任何限制；进入租户后以该租户上下文操作，仅留痕、不拦截。
2. 租户管理员只能看本租户；跨租户访问返回 403。
3. 普通用户只能进入角色勾选的页面；未授权菜单不渲染，直接访问路由与接口都返回 403。
4. 系统管理只有租户管理员与超级管理员可见，任何角色都无法获得。
5. 角色名租户内唯一；至少保留一个角色，最后一个不可删。
6. 角色只配置页面，不配置动作；页面内操作按业务状态与职责分离校验。
7. 同一期间编制人≠复核人、复核人≠批准人（**超级管理员除外**）；违反返回 409。
8. 租户到期/停用后，该租户账号的登录与接口均拒绝，已登录会话立即失效；超级管理员仍可进入排障与续期。
9. 续期后立即恢复，无需改密码、无数据丢失。
10. 一个手机号可在多个租户；某租户到期不影响其他租户。
11. 至少保留一名租户管理员；不能停用/删除自己。
12. 席位按启用中的用户计；超限拒绝新增。
13. 角色页面变更、租户续期/停用、用户启停/改角色全部进审计。
14. 每租户角色数 ≤ 30，超限拒绝新建。
15. 超级管理员不受角色权限、职责分离、租户状态的任何限制；操作留痕仅用于追溯，不拦截。
16. 一个普通用户在同一租户只能绑定一个角色；租户管理员不绑定角色。
17. 到期严格阻断、无宽限期；续期前该租户账号一律不能登录。

## 9. 与现有实现的差异（迁移输入）

| 现有 | 目标 |
|---|---|
| `platform_admin` 平台运营 | 超级管理员（层级） |
| `user_tenant.role = admin` | 租户管理员（层级，不再是角色） |
| 5 个固定角色 + 85 个角色注解 | 默认角色【运营】+ 租户自建角色 + 页面级权限 |
| `kind=external` 外部协作 | **本期移除**（入口删、能力冻结） |
| `org.expire_at` 仅展示/拦截 | 授权期全链路：开通/续期/到期任务/会话失效/提醒 |
| 无角色表 | `role` + `role_page` + 用户绑定角色 |
| 无租户管理页面细节 | 平台概览 + 租户列表 + 开通向导 + 详情/续期 |

迁移顺序：先建 `role/role_page` → 数据映射（admin→租户管理员，其余→【运营】）→ 接口按 `page_code` 校验 → 前端菜单按 `pages` 渲染 → 老 `role` 字段下线。**不做一次性重写，按可回滚的小步走。**

## 10. 分期计划

| 阶段 | 范围 | 产出 | 预估 |
|---|---|---|---|
| P1 租户与三级身份 | 租户 CRUD、授权期、到期任务、三级登录拦截、租户信息页、**超级管理员进入租户上下文** | 平台管理 + 登录改造 | 5–6 天 |
| P2 用户与角色 | 用户管理改造、角色表、页面勾选、审计 | 系统管理两个页面 | 4–5 天 |
| P3 页面权限落地 | 接口按 `page_code` 校验、前端菜单按页面过滤、会话刷新 | 页面权限生效 | 2–3 天 |
| P4 收尾 | 到期提醒、平台概览、回归与文档 | 可交付 | 2 天 |

合计约 2.5–3.5 周。可先交付 P1（租户到期硬控制是客户最敏感的点），P2/P3 紧随。
