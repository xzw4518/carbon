## 三、测试策略

1. **黑盒 API 为主**：Node 18+ 零依赖脚本直接调用 HTTP 接口，断言 HTTP 状态 + 业务码 + 数据字段。
2. **双账号/双租户对照**：管理员、填报员、复核人、批准人、平台账号按职责分离使用；新建隔离租户验证跨租户隔离。
3. **数据库作 Oracle**：MySQL 直查勾稽、孤儿、重复、审计守恒，不依赖页面展示。
4. **真实浏览器门禁**：Playwright + 本机 Chrome 跑 38 条业务路由与移动端 390px。
5. **可复跑数据卫生**：测试数据统一 `TST-R9-` / `TST R9` 前缀；结束后清理并复跑基线检查。

## 四、重点风险

| # | 风险 | 触发条件 | 影响 | 等级 | 应对 |
|---|---|---|---|---|---|
| R1 | 核算合计与明细不一致 | 因子切换、并发重算、手工改库 | 报表/决策数据错误 | 高 | 三层勾稽 SQL + 每条明细复算（本轮 39 项全过） |
| R2 | 跨租户数据越权 | 直接改 URL 中的 id | 数据泄露/篡改 | 高 | MyBatis 租户行级隔离 + 跨租户读写用例（本轮 9 项全过） |
| R3 | 权限粒度不足 | 只读用户绕过 UI 调写接口 | 误写/越权写 | 中 | 页面级权限 + 删除限 ADMIN；交付说明已写明无动作位 |
| R4 | 非法入参触发 5xx | 期间格式错、版本号非数字 | 可用性指标、错误页、告警噪声 | 中 | **T-1/T-2 已修复并回归（D11~D11d 均 400）**；保留单测防回归 |
| R5 | 上传/导出攻击 | 路径穿越、脚本附件、CSV 公式 | 客户端执行/数据外泄 | 中 | 文件名清洗、强制 attachment + octet-stream、CSV 前置单引号（本轮全过） |
| R6 | 审批链被绕过 | 状态机非法流转、锁定后改数 | 审计结论失真 | 高 | PeriodGuard + SOD + 锁定守卫（本轮全过） |
| R7 | 并发/性能 | 多人同时审批、批量导入 | 冲突/超时 | 中 | 已执行并发压测：60 写 / 25 重算 / 10 提交 / 30 读，0 个 5xx；生产容量待客户环境复测 |
| R8 | 兼容性 | 非 Chromium 浏览器、移动端 | 排版/交互异常 | 低 | Chrome/Edge + 390px 已验证；Firefox/Safari 未覆盖 |
| R9 | 回归失效 | 改校验/CORS/Cookie 后旧用例失效 | 发版回归遗漏 | 中 | 固定门禁：mvn + round9 + DB39 + L0/UI |

### T-1（P2）非法期间格式 `calculate` 返回 500

- **复现**：管理员 Bearer
  `POST /api/accounting-periods/2026-13/calculate`（或 `abc`、`2026-00`、`2026-1`）
  → HTTP 500 `{"status":"INTERNAL","body":{"message":"服务内部错误，请联系管理员"}}`
- **证据**：`logs/carbonbal.log`：`DateTimeParseException: Text '2026-13' could not be parsed...`；D11/D11b 失败。
- **根因**：`AccountingService.calculate()` 在 `YearMonth.parse(period)` 前未校验；`ReportService.requirePeriod()` 已有正则但未复用。
- **影响**：前端 URL 拼错/旧书签/脚本误传触发 5xx，污染监控与可用性指标；事务回滚，无数据损坏（DB 无 2026-13 期间）。
- **修复建议**：入口校验 `^\d{4}-(0[1-9]|1[0-2])$`，非法 → 400 `VALIDATION "核算期格式为 YYYY-MM"`；或在 `GlobalExceptionHandler` 捕获 `DateTimeParseException` → 400。补 `AccountingFlowTest` 反例。
- **修复结果（2026-11-26）**：`AccountingService.calculate()` 首行加入 `PERIOD_PATTERN` 正则校验并抛 `BizException.validation`；`AccountingFlowTest` 新增 4 种非法期间反例。回归 D11/D11b = `400 / VALIDATION / 核算期格式为 YYYY-MM`，PASS。

### T-2（P3）`review/approve` 版本号非数字返回 500

- **复现**：`POST /api/accounting-periods/2026-11/review`，Body `{"version":"abc"}` → 500；`approve` 同样。
- **证据**：日志 `NumberFormatException: For input string: "abc"`；D11c/D11d 失败。
- **根因**：控制器从 `Map<String,Object>` 取值后 `Integer.parseInt`，未捕获异常；`lock` 用 `VersionReq` 所以返回 400。
- **影响**：畸形客户端请求 5xx；无数据变化。
- **修复建议**：统一使用 `AccountingDtos.VersionReq` + `@Valid`，或安全解析后抛 `BizException.validation`。
- **修复结果（2026-11-26）**：新增 `versionOf()` 安全解析（`trim` + `parseInt`，失败抛 `BizException.validation("版本号必须为整数")`），请求体保持可选以兼容旧调用方。回归 D11c/D11d = `400 / VALIDATION`，PASS。

### T-3（P2，并发）并发重算同一期间触发 MySQL 死锁 → 500

- **复现**：隔离租户导入 60 条读数后，25 个并发 `POST /accounting-periods/2026-02/calculate`；首轮 `200×2 / 409×12 / 500×11`，日志 `Deadlock found when trying to get lock; try restarting transaction`。
- **根因**：`calculate()` 无期间级串行化，并发建期与版本更新交叉持锁；死锁异常未映射为可重试的 4xx。
- **影响**：两人同时点"重新计算"或重复提交时 500 与告警；事务回滚，无数据损坏。
- **修复结果（2026-11-26）**：`calculate()` 改为 `SELECT ... FOR UPDATE` 取期间行锁；期间不存在时用 `INSERT ... ON DUPLICATE KEY UPDATE` 幂等建期；`GlobalExceptionHandler` 将死锁/锁等待超时映射为 `409 VERSION_CONFLICT`。
- **回归**：预热建期后 25 并发重算 **25×200**；首次并发建期无 5xx（个别 409 可重试）；60 并发写读数 60×200；10 并发同版本提交恰好 1 成功；30 并发读快照全 200。

### D-1（P3，文档）开通租户响应与文档不一致

- 文档 `user-system-api.md` §4.3 示例含 `defaultRole`，实际响应无该字段。建议补返回字段或修正文档（本轮按实际契约断言通过）。

### S-1（P3，安全加固，已修复）CORS 反射任意 Origin

- **复现（修复前）**：`OPTIONS /api/products`，`Origin: http://evil.example` → 200 并回显该 Origin。
- **修复**：`SecurityConfig` 改为读 `app.cors.allowed-origins`（默认空=不开放跨域），生产用 `CORS_ALLOWED_ORIGINS` 显式配置；保持 `allowCredentials=false`。
- **回归**：evil Origin 与未配置来源预检均返回 **403**，无 `Access-Control-Allow-Origin`。

### S-2（P3，安全加固，已修复）Cookie 缺 `Secure`

- **修复**：新增 `app.auth.cookie.secure`（默认 false，生产 `AUTH_COOKIE_SECURE=true`），登录与退出清理均按开关设置。
- **回归**：开关开启时 `cb_token`/`cb_csrf` 均带 `Secure`；`cb_token` 保持 `HttpOnly`、`SameSite=Lax`。

### S-3（P3，安全加固，已修复）应用侧安全头不完整

- **修复**：Spring Security 输出 `Content-Security-Policy` 与 `Referrer-Policy: strict-origin-when-cross-origin`，保留 `X-Frame-Options: SAMEORIGIN`、`nosniff`；`nginx-https.conf` 同步增加 CSP。
- **回归**：真实 CSP（不 bypass）下首屏渲染正常、无违规；Chrome/Edge 38 路由 0 控制台错误。

### O-1（观察项）退出登录不吊销 Bearer

- `POST /api/auth/logout` 仅清 Cookie，Bearer 在 8h TTL 内仍可用。建议在交付说明写明；如需强制失效，增加 token 版本或黑名单。

### O-2（观察项）数值超范围提示不准确

- `l1=1e30` 返回 400，但文案为"输入内容超出字段长度限制"；建议把 `Out of range` / `Incorrect decimal` 分支前置，提示"数值超出允许范围"。
