# 第十四批交付报告：角色与页面权限（用户体系重构 P2）

> 日期：2026-11-26　范围：P2（角色表 + 页面级权限 + 用户管理改造）
> 依据：`user-system-redesign.md`（D4–D8）、`user-system-api.md`、原型 `prototypes/user-system-v2.html`

## 1. 本批做了什么

| # | 能力 | 结果 |
|---|---|---|
| 1 | 角色表 | `tenant_role` + `tenant_role_page`（V108）；每个租户默认角色【运营】自动创建并绑定 34 个页面 |
| 2 | 角色 CRUD | `/api/roles`：列表（含用户数/页面数）、页面目录、详情、新建、修改、删除、角色用户 |
| 3 | 角色约束 | ≤30 个；名称唯一；默认角色不可删；有用户不可删；至少保留一个；`home` 必选 |
| 4 | 三级身份 | `user_tenant.user_type`（tenant_admin / user）+ `role_id`；旧的 filler/reviewer 等自动归一为 user |
| 5 | 用户管理 | 新增/编辑改为“用户类型 + 角色”；列表展示层级与角色名，支持按类型/角色筛选 |
| 6 | 页面下发 | JWT 增加 `pages` 声明；`/auth/me` 返回 `pages`、`userType`、`roleId`、`roleName` |
| 7 | 接口校验 | `JwtAuthFilter` 按 URI → `page_code`；未授权 403 `PAGE_FORBIDDEN` |
| 8 | 快照裁剪 | `/api/bootstrap` 按页面移除数据键，避免“藏了菜单却能看到数据” |
| 9 | 前端菜单 | 菜单项补 `page` 编码；按 `pages` 过滤，分组无可用项整组隐藏 |
| 10 | 路由守卫 | 直接输入未授权 hash 显示“没有该功能的访问权限”，不再渲染业务页面 |
| 11 | 角色管理页 | `/system/roles`：KPI、列表、页面树（13 组 34 页）、分组全选、实时计数 |
| 12 | 会话失效 | 角色改动让该角色下成员 `token_version+1`，旧令牌立即 401 |

## 2. 数据与接口

- 迁移 **V108**：2 张新表、`user_tenant` 加 2 列、默认角色与页面回填、旧角色归一；Flyway 到 **108（26 个迁移）**。
- 新增接口 **7 个**（162 → 169）：`GET/POST /api/roles`、`GET /api/roles/pages`、`GET/PATCH/DELETE /api/roles/{id}`、`GET /api/roles/{id}/users`。
- 新错误码 4 个：`PAGE_FORBIDDEN`(403)、`ROLE_LIMIT`(409)、`ROLE_IN_USE`(409)、`ROLE_DEFAULT`(409)。
- 表：38 张业务表（物理 39）。

## 3. 权限模型（定稿）

- **层级决定身份**：超级管理员 / 租户管理员 / 普通用户。
- **角色只决定页面**：34 个业务页面，13 个分组；不含动作位、不含数据范围。
- **动作不按角色分级**：能进页面即可新增、编辑、流转、复核、批准；唯一护栏是“删除/移出仅租户管理员”。
- **系统管理不下放**：账号、角色、租户信息、审计只属于租户管理员与超级管理员，不进入页面目录。
- **职责分离仍是业务规则**：同一期间编制≠复核≠批准，按人校验；超级管理员不受限。

## 5. 兼容与迁移

- 旧角色名（filler/reviewer/approver/viewer）在登录时自动映射为 `user`，不影响存量账号。
- 存量成员全部绑定默认角色【运营】（34 页），行为与升级前一致。
- 原 `@PreAuthorize("hasAnyRole('ADMIN','FILLER')")` 等 48 处统一改为 `ADMIN|USER`；38 处管理类接口保持仅 ADMIN。

## 6. 边界

- 动作权限、数据范围（SELF）未纳入角色模型；`data_scope` 字段保留但不在新 UI 中作为角色配置项。
- 删除类动作仍限租户管理员，属于有意保留的护栏，不是遗漏。
- 页面编码一旦发布不可修改；新增页面需同步 `PageCatalog`、`menu.js` 与角色默认绑定（启动自动补齐）。

## 7. 修复记录（2026-11-26）

| 问题 | 原因 | 修复 |
|---|---|---|
| 超级管理员登录后仍能看到全部业务菜单 | 平台令牌被签发 `pages=*`，前端按“全部页面”渲染 | 平台令牌改为空页面集合（`-`）；`/auth/me` 返回空 `pages`；登录后自动落到「平台管理 → 租户管理」 |
| 平台账号可调用业务只读接口 | 过滤器对 `platform_admin + orgId=0` 提前放行，跳过了页面校验 | 页面校验前移到平台分支之前，平台账号访问业务接口返回 403 `PAGE_FORBIDDEN`；前端不再为平台账号请求 `/api/bootstrap` |
| 登录跳转瞬间偶发 `cfg.title` 报错 | 页面模块尚未加载时 hashchange 触发渲染 | `render()` 对未注册路由直接返回；空分组仅在“全部页面”时显示 |
