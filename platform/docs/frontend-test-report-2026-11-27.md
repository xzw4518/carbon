## 2. 测试方法与判定口径

- 真实浏览器点击与输入，不使用 mock；登录必须从 SVG 图形验证码中提取字符，与用户路径一致。
- 表单反例仅验证拦截文案，**不提交有效数据**；批量删除只验证按钮状态，不点确认；报告“生成”只验证入口，不执行生成。
- 页面渲染判定：`#view .page` 存在、面包屑标题与菜单一致、导航高亮、无 `NaN/[object Object]`、控制台 0 error。
- 越权判定：受限账号访问无权页面时显示“没有该功能的访问权限”，且不发起对应数据请求。
- 全流程监听非 GET 请求，除登录/登出外出现写请求即视为数据风险。

## 4. 缺陷与问题清单（按严重程度排序）

### BUG-01（P1，高，流程阻塞，已修复）运营账号看不到“复核 / 批准”入口

- **复现步骤**
  1. 使用运营账号 `13800000002 / Test@2026!Pass` 登录，进入「碳排放核算」。
  2. `GET /api/auth/me` 返回 `role=user`。
  3. 页面执行 `CarbonAPI.canReview()`、`CarbonAPI.canApprove()` 均为 `false`。
  4. 当核算期为 `submitted` 时只渲染“查看”，无“复核”；为 `reviewed` 时无“批准”。
- **根因**
  - [api-client.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/api-client.js#L180-L182) 仅将 `admin/reviewer/approver` 视为可复核/批准；
  - [AuthStateService.java](file:///d:/能碳12/platform/backend/src/main/java/com/carbonbal/auth/AuthStateService.java#L72) 把历史岗位统一归一为 `admin/user`，导致 `role` 永远不是 reviewer/approver；
  - [pages-core.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/pages-core.js#L194-L209) 依据上述能力决定“复核/批准”按钮是否渲染；
  - 而后端 [AccountingController.java](file:///d:/能碳12/platform/backend/src/main/java/com/carbonbal/accounting/AccountingController.java#L40-L56) 实际允许 `ADMIN/USER` 调用审批接口，[AccountingService.java](file:///d:/能碳12/platform/backend/src/main/java/com/carbonbal/accounting/AccountingService.java#L187-L246) 通过“编制人/复核人/批准人”做职责分离。
- **影响范围**：所有非管理员账号的核算流转；运营提交后无法在界面完成复核；若唯一管理员同时是编制人，会被“复核人不能是编制人”阻断，流程只能通过 API 或新增管理员绕行。
- **修复建议**：在角色编辑器增加“岗位/权限点”（复核、批准）并透传到 `/auth/me`；前端按权限点而非 `role` 字符串判断。过渡期至少让 `role=user` 渲染复核/批准按钮，由后端职责分离返回明确错误。

- **修复**：[api-client.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/api-client.js#L180-L182) 的 `canReview/canApprove` 纳入 `role=user`，与后端 `@PreAuthorize('ADMIN','USER')` 对齐；职责分离仍由服务端按“编制人/复核人/批准人”强制。

### BUG-02（P2，中，校验缺失，已修复）选填数值字段的负数未做前端下限校验

- **复现步骤**
  1. 管理员进入「产品列表」→ 新建。
  2. 名称留空（用于阻断保存）、单位选“吨”、1 级单位产品能耗值填 `-1`，点击保存。
  3. 仅提示“产品名称 必填”，未提示“不能小于 0”。若名称填写完整，会向 `POST /api/products` 发起请求（本次被服务端拒绝，产品数仍为 5）。
- **根因**：[pages-generic.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/pages-generic.js#L377-L385) 的数值下限校验写在 `if (!f.req) return;` 之后，所有选填 `number` 字段永远不会走 `min` 校验。
- **影响范围**：产品 `l1/l2/l3`、配额“下年度配额”等全部选填 `number` 字段；无效数据到达服务端，依赖后端兜底，错误提示滞后且不精确。
- **修复建议**：把 `min/max/step` 校验移出必填分支，对全部 `number` 字段统一校验并带字段名文案；后端保留现有兜底。
- **修复**：[pages-generic.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/pages-generic.js#L377-L389) 已把 `min/max` 与 `NaN` 校验移出必填分支，选填数值同样拦截。

### BUG-03（P3，低，权限一致性，已修复）隐藏路由 `/carbon-monitor` 绕过页面权限

- **复现步骤**
  1. 运营账号登录，地址栏输入 `#/carbon-monitor`。
  2. 页面直接渲染「在线监测 / 模块未开通」，未出现 403。
  3. 平台账号 `13900000000` 同样可访问。
- **根因**：该路由在 [pages-core.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/pages-core.js#L2076-L2093) 注册，但不在 [menu.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/menu.js) 中；[framework.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/framework.js#L239-L251) 的 `guardOfPath` 仅遍历 MENU，返回 `null` 即放行。实测已注册路由 42 条，菜单 41 条。
- **影响范围**：当前仅占位页，无业务数据；若后续补充数据或操作，将成为所有登录用户的越权入口。
- **修复建议**：将隐藏路由纳入 MENU 并绑定页面编码，或对“未登记路由”统一 403/404；增加路由一致性门禁（`UI.routes ⊆ MENU ∪ 白名单`）。

- **修复**：[framework.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/framework.js#L590-L597) 对“已注册但未纳入 MENU”的路由统一按无权访问拦截；未知路由仍回退首页。

### OBS-01（P3，低，体验，已修复）接口异常提示暴露英文技术文案

- **复现**：拦截 `/api/products` 请求后进入产品列表，页面 toast 显示 `Failed to fetch`（用例 H06 页面未白屏、降级正常）。
- **修复**：[api-client.js](file:///d:/能碳12/platform/backend/src/main/resources/static/app/assets/api-client.js#L60-L72) 将浏览器网络层异常统一映射为“网络异常，请检查网络连接后重试”，技术细节输出控制台。

## 5. 重点风险与回归建议

| 风险 | 说明 | 回归建议 |
| --- | --- | --- |
| 核算流转角色模型 | 前端审批入口与后端岗位/职责分离不一致（BUG-01） | 修改后覆盖 admin/运营 两个账号的 计算→提交→复核→批准→锁定 全链路，校验“编制人≠复核人≠批准人” |

| 异常文案 | 网络异常直接透传英文 | 断网/超时/5xx 三类场景回归 toast 文案 |
