# 全维度测试方案与问题排查报告 · 2026-11-27

> 被测系统：能碳管理平台 v1.0.0（Spring Boot 3.2.5 + MySQL 8.0.28 + 原生 SPA）
> 运行信息：`http://localhost:8088/app/`；MySQL 127.0.0.1:3307/carbonbal；Flyway V114（32 个迁移）
> 规模：31 个控制器 / 183 个接口映射 / 41 条前端路由（38 个业务页 + 3 个平台页）
> 数据基线：1 租户、6 账号、5 产品、6 设备、5 设施、7 供应商、3 报告、期间 2026-11 = draft
> 账号：13900000000/Superadmin@2026!Pass、13800000001/Admin@2026!Pass、13800000002~05/Test@2026!Pass

## 一、结论摘要

- 自动化基线 **468 项全部通过**（104 单测 + 142 功能 + 100 E2E + 38 UI 流程 + 5 渲染 + 11 静态 + 33 数据 + 21 文档 + 14 性能），2 条 E2E 失败为短信通道日配额（环境外）。
- 本轮重点排查了**并发、安全、兼容、启动可靠性**四个此前薄弱面：并发计算的死锁 500 已被“行锁串行化 + 409 映射”修复，10 并发实测全 200；CORS/CSP/安全头已加固并验证；768/1024 视口无溢出。
- 决策后已处理：**初始口令统一改为 15~21 位强口令**、**软删唯一键两处已修（供应商释放名称 / 能源管理同日期复活）**；**只读角色不再作为缺陷**（系统未内置只读角色，已改文档口径）；**dist 待发版指令重打**。仍存：测试与演示共库。

## 三、重点风险（按可能性 × 影响排序）

| # | 风险 | 触发条件 | 影响 | 现有控制 | 等级 |
|---|---|---|---|---|---|
| R1 | 并发写同一核算期导致死锁/500 | 多人同时点“计算” | 操作失败、版本错乱 | 已加 `select … for update` + 死锁→409；10 并发实测全 200 | 中→低 |
| R2 | 接口层不区分读写（无只读角色） | 拿到 viewer 令牌直接调写接口 | 数据被非预期修改 | 系统未内置只读角色；`HANDOVER` §8 已声明边界，演示以 UI 路径为准 | 低（已定性） |
| R3 | 测试污染演示库 | 跑 functional/e2e/ui-flows | 期间被推进、出现 TST 数据 | `reset-demo.sh` + ui-flows 自动收尾 | 中 |
| R4 | 口令强度 | 弱口令 | 撞库风险 | 初始口令已统一为 15~21 位强口令（含大小写/数字/符号） | 低 |
| R5 | 软删后同键重建被拒 | 删除供应商/能源管理后重建同键 | 用户被卡住 | 供应商删除时释放名称；能源管理同日期自动复活；角色为物理删除 | 低（已修） |
| R6 | 导入宽松：缺列补默认值、多列错位 | Excel 截断/多余逗号 | 口径错误 | 已按行返回 warnings + 中文错误 | 低→已缓解 |
| R7 | PDF 版式（长表格/中文折行） | 数据量大、名称长 | 遮挡、串行 | `PdfLayoutTest` 3 条 + 渲染核对 | 低 |
| R8 | 会话与令牌 | 改密、停用、多端登录 | 旧令牌仍可用 | 改密/停用 bump `token_version`，实测 401 | 低 |
| R9 | CSP 与前端产物 | 新增内联脚本 | 页面白屏 | CSP 含 `'unsafe-inline'`；发布前需 `sync-frontend --check` | 低 |
| R10 | 启动依赖环境变量 | 漏 `JWT_SECRET`/`DB_PASSWORD` | 服务起不来 | 新增 `tools/run-prod.sh` fail-fast；进程需独立启动 | 中 |

## 六、已发现缺陷（按严重程度）

### P1

**B-01 并发计算同一期间触发数据库死锁 → 500**
- 复现：同一账号 10 个并发 `POST /api/accounting-periods/{p}/calculate`；日志出现 `DeadlockLoserDataAccessException ... UPDATE accounting_period ... WHERE (id=? AND version=?) AND org_id=...`，接口 500。
- 影响：多人同时点“计算”会失败并产生 5xx，前端只显示“系统繁忙/未知错误”，重试才能成功。
- 根因：`calculate` 先读后写，无锁，多个事务交叉更新同一行。
- 建议/已做：`AccountingPeriodMapper.selectForUpdate`（`select ... for update`）串行化同期间计算；`GlobalExceptionHandler` 将 `DeadlockLoserDataAccessException`/`CannotAcquireLockException` 映射为 409「系统繁忙，请稍后重试」。**本轮 10 并发复测：10/10 返回 200，无 5xx。**

### P2

**B-02 供应商「备注」填了不保存（已修复）**
- 复现：编辑供应商→备注填任意值→保存（提示“已保存”）→重开为空；列表“备注”列恒为「—」。
- 影响：静默数据丢失。
- 建议/已做：新增 `V114__supplier_remark.sql`，实体/DTO/Service/前端全链路接通；回归通过。

**B-03 性能门禁自验证码上线后一直登录失败（已修复）**
- 复现：`bash tools/perf.sh` → `[FAIL] 登录失败，无法采样`。
- 影响：14 项性能预算长期未真正执行，属“门禁绿灯假象”。
- 建议/已做：脚本先取图形码再登录；修复后 14/14 达标。

**B-04 接口层不区分读写（已定性，非缺陷）**
- 现象：viewer 令牌 `POST /api/products` → 200。
- 定性：系统**未内置只读角色**，所有业务账号在接口层同为 `USER`，权限只表现为页面集合与前端按钮。已在 `HANDOVER` §8 写明边界，`README`/`architecture` 的“只读”表述同步修正。
- 后续（如需）：角色增加动作位（read/write/approve），接口按动作位鉴权。

**B-05 导入缺列/多列静默处理（已修复）**
- 复现：产品导入只填前两列 → success=1，类型/分类/单位被默认值填充且无告警。
- 建议/已做：按表头列数逐行比对，少列/多列均返回 `warnings`；解析错误改中文提示。

**B-06 上传文件名未清洗（已修复）**
- 复现：文件名 `../evil.csv` → 入库与下载头均保留该名（落盘为 UUID，无目录穿越）。
- 建议/已做：`sanitizeName()`（basename/去控制字符/去前导点/限长 200）。

### P3

**B-07 分析图 Top 8 与 KPI 全量口径不一致（已修复）** — series 名称在 >8 家时标注「（Top 8）」。
**B-08 PDF 页脚 `[MACHINE]` 摘要行（已修复）** — 改为配置开关，生产默认关闭。
**B-09 软删唯一键残留（已修复）** — 供应商删除时把 name 改为 `原名#id`（唯一键是 org+name+product，释放后可同名重建）；能源管理唯一键是 (org, at_date)，改为“同日期的软删记录自动复活”（保留 id 与审计链）；角色删除本就是物理删除，实测同名重建 200。
**B-10 非法版本号返回 500（已修复）** — review/approve 传 `version:"abc"` 曾抛 `NumberFormatException`；现 400「版本号必须为整数」。
**B-11 启动缺少 JWT_SECRET 直接失败，无友好提示（已缓解）** — 新增 `tools/run-prod.sh` fail-fast 校验。
