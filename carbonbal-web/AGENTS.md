# AGENTS.md · 能碳管理平台前端

本文件是本项目的硬约束入口。任何 agent/协作者开始改动前先读本文件；冲突时以本文件 + 主规范《软件项目开发机制体系_通用版_v1.1》为准。

> 2026-11-25 起本项目进入**正式前端**阶段：页面随 Spring Boot 发布到 `/app/`，数据全部来自后端接口，不再保留 mock 兜底。下文凡标注「原型边界豁免」的条款同时失效，按主规范执行。

## 1. 项目事实

- 形态：正式前端（`index.html` + `assets/`），Hash 路由，随 Spring Boot 单 jar 发布，接口统一 `/api/*`。
- 数据：`window.DB` 由 `GET /api/bootstrap` 注入（字典/KPI/首页聚合/台账快照），写操作走各域接口；禁止在页面里写死业务数据。
- 规模：41 个导航入口；6 个分析页 + 3 个报告页 + 14 个台账页 + 首页/企业信息/监测/预警等。
- 目标：信息架构、字段、交互保持一致；视觉为自研绿色主题。
- 启动：先启后端，再访问 `http://localhost:8088/app/`；源码同步用 `platform/tools/sync-frontend.sh`。
- 门禁：`node tools/gate-l0.cjs`（L0 静态 11 项，零依赖）+ `node tools/check-ui.cjs`（L1 UI，遍历 38 条路由，需 playwright-core）+ `node tools/ui-flows.cjs`（L2 交互 37 项，真实点击，需服务已启动）。三条都 PASS 才能交付。

### 3.1 六种必须停的情况（不许「先做着看」）

需求歧义、约束冲突、P0 输入缺失、门禁连续两次失败、安全红线、成本超预算 → 停止并说明；恢复条件为「缺项补齐 / 门禁转绿 / 风险被用户书面接受」。超时未恢复升级给用户。

### 3.2 交接五件套（每次交付结尾）

`artifact`（改动文件路径）/ `decision`（≤3 条关键决定）/ `assumptions`（假设与待确认项）/ `next`（1–3 条后续）/ `verification`（验证命令与结果）。缺一项视为未完成。

### 3.3 事实与假设

结论必须区分事实（有两个来源或一次可复现实验）与假设；假设写进交接物，并标「什么证据会推翻它」。禁止静默假设。

## 4. 决策分级（本项目）

| 级别 | 例子 | 处理 |
|---|---|---|
| D0 | 文案、间距、单页样式、修复无效图标 | 直接改，回复记一行 |
| D1 | 跨页组件、筛选/表单交互、枚举选项 | 说明方案与影响面后改，跑 gate |
| D2 | 页面增删、路由/信息架构、数据模型、字段语义、用户可见流程变化 | 先给需求卡，等用户确认 |
| D3 | 发布分享链接、删除数据/文件、权限变更 | 用户批准 + 回滚点 |

**爆炸半径阈值**：改动涉及 ≥2 个模块（`pages-core` / `pages-generic` / `framework` / `data` 为模块单位），或影响 ≥5 个页面/入口，自动升 D2。

> 同一缺陷的连带修复（例如组件改签名 + 三处调用同步）按一个改动单元计，不因跨文件而升级；但若连带改动引入新的用户可见行为，仍按 D2。

**职责分离**：生产者不做最终审查。每次改动后以「审查视角」独立复验（换检查清单，不是复述实现），Critic 结论写入回复的「未覆盖项」。

## 7. 已知边界

- 数据全部来自后端（MySQL 8）；前端不再有 mock，断网/无后端时页面不可用。
- 短信实名通道、域名与 HTTPS 证书由客户环境负责，不在本次交付范围；包内保留模拟通道与自签/nginx 参考配置。
- 14 个台账已服务端分页；分析页为聚合接口，不做明细钻取。
- 首页缺“含数字的结论句”（M17）；M18 复盘已建立，等待首次真实用户复盘。
- 外部协作仅支持报告/期间/足迹三类授权，不支持字段级授权。
- 文件上传/PDF 预览为前端模拟，使用 `assets/sample-report.pdf`。
- 主题切换只改变色变量，不重绘图表序列色；图表固定品牌绿。
- 一致性优先于自研规范：当机制要求与既有信息架构/密度冲突时，以一致性为准并登记受限项。
