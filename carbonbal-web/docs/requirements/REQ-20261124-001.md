## 一、方案

**目标**：填报员把设备读数导入平台，系统按因子版本算出某月 scope1/scope2 排放量，管理员提交并锁定，任何人可下载与页面数字一致的 PDF 报告；全过程可追溯到人和时点。

**旅程（5 步）**
1. 登录 → 进入「设备数据」，CSV 导入当月读数（或手工补录）
2. 进入「碳排放核算」，选择月份，点「计算」→ 生成明细（每条读数 × 对应因子）
3. 核对明细与合计，点「提交」→ 状态变为已提交，编辑被拒
4. 管理员点「锁定」→ 期间冻结，任何写入返回 409
5. 点「生成报告」→ 服务端出 PDF，页面/接口/PDF 三处合计一致

**不做清单**
- 不做 scope3（价值链）
- 不做多租户计费与套餐
- 不做设备协议直连（Modbus / OPC UA / MQTT）
- 不做报告模板自定义与多语言
- 不做移动端
- 不做碳足迹（产品维度）——单独切片

## 二、字段设计（表结构草案）

| 表 | 关键列 | 说明 |
|---|---|---|
| `org` | id, name, code | 单企业起步，预留 org_id |
| `device` | id, org_id, name, code, energy_type, unit, status | 由现有设备树扁平化 |
| `device_reading` | id, device_id, ts, qty, unit, rate, source, status, created_by | `ts` 带时区；`source ∈ 自动采集/手工补录` |
| `emission_factor` | id, category, fuel, unit, value, source_doc, scope, org_id, version, review_status, effective_from, effective_to | **三级因子**：`scope ∈ national/local/customer`，`customer` 必带 `org_id`；`review_status ∈ pending/approved`，仅 approved 参与计算 |
| `accounting_period` | id, org_id, period(YYYY-MM), status, scope1, scope2, total, calc_version, locked_at, locked_by | `status ∈ draft/calculated/submitted/locked` |
| `period_unlock` | id, period_id, reason, requested_by, approved_by, at | 解锁申请与审批留痕；每次解锁对应一条 |
| `accounting_line` | id, period_id, reading_id, factor_id, activity, emission | 一行 = 一条读数 × 一个因子，可回算 |
| `report` | id, period_id, calc_version, file_key, sha256, generated_at, generated_by | 报告绑定核算版本，重算不覆盖旧报告 |
| `audit_log` | id, entity, entity_id, action, before_json, after_json, actor, at | **只追加**，不更新不删除 |

**口径（唯一算式，只在后端实现一处）**
- 因子选取优先级：**客户自定义 > 地方指南 > 国家缺省值**；同层级同 fuel 同时段只能一条 `approved`
- `scope1 = Σ(化石燃料用量 × 燃料因子)`（天然气 / 柴油 / 汽油）
- `scope2 = Σ(外购电量 × 电网因子) + Σ(外购蒸汽 × 热力因子)`
- `total = scope1 + scope2`（保留 2 位，前端只展示接口值）
- 重算 = 新建 `calc_version`，旧版本与旧报告不变

**状态机**
```
draft ──calculate──> calculated ──submit──> submitted ──lock──> locked
  ^                      ^                                        │
  └────── unlock（仅管理员 + 原因 + 审计）───────────────────────┘
```
- `locked` 下任何写操作返回 409 `PERIOD_LOCKED`
- `unlock` 必须写 `period_unlock`（原因 + 申请人 + 审批人），并把期间退回 `draft`
- 解锁后重算生成新 `calc_version`，原报告保留可下载

## 三、接口清单（17 个，够跑通链路）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/login` | 返回会话 token + 角色 |
| GET | `/auth/me` | 当前用户与权限 |
| GET | `/devices` | 设备列表（分页/筛选） |
| GET | `/device-readings` | 读数列表（设备、日期区间） |
| POST | `/device-readings` | 单条新增（幂等键 `clientRequestId`） |
| PATCH | `/device-readings/:id` | 修改（带 version 乐观锁） |
| POST | `/device-readings/import` | CSV 导入，返回成功/失败行 |
| GET | `/emission-factors` | 因子列表（按类别 + 生效日 + 层级） |
| POST | `/emission-factors` | 新增客户自定义因子（仅管理员，`review_status=pending`） |
| POST | `/emission-factors/:id/review` | 审核通过（仅管理员） |
| POST | `/accounting-periods/:period/calculate` | 计算并生成明细 |
| GET | `/accounting-periods/:period/lines` | 明细与合计 |
| POST | `/accounting-periods/:period/submit` | 提交（draft/calculated → submitted） |
| POST | `/accounting-periods/:period/lock` | 锁定（submitted → locked，仅管理员） |
| POST | `/accounting-periods/:period/unlock` | 解锁（locked → draft，仅管理员，必填 reason） |
| POST | `/reports` | 生成报告（服务端 PDF） |
| GET | `/reports/:id/download` | 下载（带 sha256 校验） |
| GET | `/audit-logs` | 按实体查改前/改后 |

**统一信封**：`{ status: 0|错误码, body: {} }`；鉴权顺序 401 → 403 → 400 → 409。
**错误码（先冻结这 6 个）**：`UNAUTHORIZED(401)`、`FORBIDDEN(403)`、`VALIDATION(400)`、`PERIOD_LOCKED(409)`、`VERSION_CONFLICT(409)`、`FACTOR_MISSING(422)`。

## 五、验收断言（可执行，逐条进 L1/L3 门禁）

1. 新增读数 → 刷新页面仍在 → `audit_log` 有 1 条 `create`
2. 修改读数 → 审计记录 `before/after` 两版值
3. 核算：3 条读数 + 2 个因子，`total = Σ(activity × factor)`，用源表重算误差 = 0
4. 提交后 `PATCH` 读数 → 409 `PERIOD_LOCKED`
5. 两个会话同时改同一读数 → 后提交者收到 409 `VERSION_CONFLICT`，提示刷新
6. 报告 PDF 内合计 = 页面合计 = 接口 `total`（三处一致）
7. 因子换版本重算 → 新 `calc_version`，旧报告 sha256 不变
8. 查看者角色 POST 读数 → 403，且不回显他人数据
9. 解锁：管理员填原因解锁 → 期间回 `draft` → `period_unlock` 有记录 → 重算生成新 `calc_version`，旧报告仍可下载且 sha256 不变
10. 因子优先级：同一 fuel 同时段存在 national + customer 两条 approved 因子 → 计算取 customer 值
