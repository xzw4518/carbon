## 一、方案

- **目标**：让“四岗职责分离”在界面上真的走得通，而不是后端有接口、前端没入口。
- **旅程**：填报员建期并计算 → 提交 → 复核员复核 → 批准人批准 → 管理员锁定 → 需要修改时解锁并留原因。
- **不做清单**（H1 已确认）：
  - 不做自定义角色/审批流配置；
  - 不做跨页全选批量删除；
  - 不改后端状态机（解锁回 draft）；
  - 不为 viewer 做独立只读页面（同一页面按角色隐藏）。

## 二、字段与数据契约

| 项 | 位置 | 口径 | 真相源 |
|---|---|---|---|
| 当前角色 | `CarbonAPI.me().role` | `admin/filler/reviewer/approver/viewer` | JWT + `/auth/me` |
| 核算状态 | `accounting_period.status` | `draft/calculated/submitted/reviewed/approved/locked` | 库表 |
| 复核/批准接口 | `POST /api/accounting-periods/{period}/review|approve` | 需 `version`；SoD 冲突 409 | 后端 |
| 批量删除 | `CarbonAPI.deleteRows` | 逐条 `DELETE /api/<resource>/{id}`，汇总成功/失败 | 各域接口 |
| 预警统计 | `GET /api/alert-records/stats` | `unread/open/highOpen/midOpen` | `alert_record` |
| 预警筛选 | `/api/alert-records` | `keyword/metric/device/level/status/isRead/from/to` | `alert_record` |

## 四、验收标准（AC）

1. 填报员在 `2026-11` 点“计算”后状态“已计算”，点“提交”后“已提交”，操作列只剩“查看”。
2. 复核员看到“复核”，确认后状态“已复核”；批准人看到“批准”，确认后“已批准”。
3. 管理员看到“锁定”，锁定后“已锁定”；解锁填原因后回“草稿”。
4. viewer 产品页按钮集合不含“新建/编辑/删除/导入/批量删除”；核算页操作列只有“查看”。
5. 管理员勾选 2 条产品批量删除，提示“成功 2 条，失败 0 条”，total 减 2。
6. 预警记录页初始 3 条，KPI 2/2/1/1；按“排放量”筛选 1 条；重置恢复 3 条。
