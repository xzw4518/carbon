# 需求卡模板（M01 最小三段式）

> 触发条件（D2 四类，任一命中即先填卡、等确认）：页面增删 / 路由或导航层级变更 / 数据模型或字段语义变更 / 用户可见流程变更。
> 单页样式、文案、间距、枚举选项、组件统一属 D0–D1，不填卡，直接在回复里写「目标/影响面/验收」。
> 规则来源：M01 需求可执行化；§10.7 需求卡；§10.15 红线。

---

## 一、方案（一句话能说清）

- **目标**：谁在什么场景下完成什么，完成后哪个指标/体验变好。
- **旅程**（3–5 步）：进入页面 → 筛选 → 查看 → 操作 → 反馈。
- **不做清单**（必须非空）：本次明确不做的事，防范围膨胀。

## 二、字段设计（不能省）

| 字段 | 位置（`表.列` / 表单控件 / 表格列） | 必填 | 口径 / 枚举 | 真相源 |
|---|---|---|---|---|
| 例：`period` | `production_value.period` / 月份选择器 / 第 2 列 | 是 | `YYYY-MM`，区间含首尾 | 后端库表 |

> 一个字段只能有一个真相源（库表列）；同一枚举改动必须同步「数据 / 表单 / 筛选 / 表格 / 图表」五处。
> 字段口径以 `docs/字段与口径.md` 为准；测试数据用 `TST-` 前缀并在交付前清理。

## 三、执行清单

| # | 任务 | 产出文件 | 验收（可断言） |
|---|---|---|---|
| 1 | 例：筛选增加月份范围 | `pages-generic.js` | 选某两个月 → total 与 SQL 一致；重置恢复 |

## 四、验收标准（AC）

每条必须**原子、可量化、可取证**。以下形容词禁止出现在 AC 中：

> 良好、流畅、美观、基本可用、正常、合理、友好、大致、差不多

合格示例：

- 「点击月份输入框 → 面板展开，含 12 个可点月份，选中项背景为品牌绿」
- 「选项区间 2026-10 ~ 2026-11 → 列表行数由 5 变为 4，日期列均落在区间内」
- 「重置后输入框为空，列表恢复 5 行」

## 五、需求卡头（登记用）

```yaml
card_id: REQ-20261124-001     # 日期 + 当日序号，不复用、不随标题变
status: draft                  # 只有用户确认后才可 approved
domain: "02 数据与分析"         # 01 流程 / 02 数据 / 03 集成 / 04 内容 / 05 通知 / 06 交易 / 07 合规 / 08 运营
source_quotes: ["用户原话，保留不改写"]
assumptions: []                # 假设必须显式，不能当事实
open_questions: []             # 谁回答、何时
acceptance_criteria: []        # 对应第四节
```

## 六、已填示例（本月实际需求）

```yaml
card_id: REQ-20261123-014
status: approved
domain: "02 数据与分析"
source_quotes: ["碳足迹核算页面的核算日期筛选条件，参考竞品的做法，点击后弹出组件选择月份"]
assumptions: ["竞品该页无日期控件，按其其他月份控件的交互补全；用户已确认按月份范围实现"]
open_questions: []
```

| 段 | 内容 |
|---|---|
| 目标 | 用户在产品碳足迹核算页按月份区间筛选核算记录 |
| 不做 | 不做自定义季度、不做跨年快捷选项、不改表格列 |
| 字段 | `footprint.date`（`YYYY-MM-DD`）→ 月份区间比较取前 7 位；筛选状态 `fpState.from/to` |
| AC | ① 点击输入框弹面板；② 两次点选成区间并回填 `2026-10 ~ 2026-11`；③ 查询后仅保留区间内记录；④ 重置清空并恢复全量 |
