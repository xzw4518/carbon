## 六、五要素问题清单

### 阻断级（P0）

#### P0-1 测试清理脚本可删除真实租户，且在当前 H2 环境下完全失效

- **① 问题描述**：`cleanupTestTenants()` 以 `org_id <> 1` 为条件删除角色、成员、产品、设备、资产、租户，并以 `phone like '135%'` 删除账号；无 profile/环境断言。`mvn test` 使用 H2 时 MySQL 多表 DELETE 语法不支持，每个套件都抛 `bad SQL grammar` 并被 catch 吞掉，24 个套件清理全部失败；若以 `-Dspring.profiles.active=prod` 连真实库运行，将删除 1 号租户以外的全部数据。
- **② 测试 bug 点**：`platform/backend/src/test/java/com/carbonbal/ApiTestSupport.java:128-147`（131 行首条多表 DELETE，148-151 吞异常）。
- **③ 最优修改方案**：清理逻辑加 `@EnabledIf`/`assumeTrue` 仅允许 H2；多表 DELETE 改为按外键顺序的单表 DELETE 或 `@Sql` 脚本；catch 改为记录并失败；测试结束断言残留为 0；禁止测试代码出现跨租户全删。
- **④ 修改目的**：消除测试导致生产数据丢失的风险，恢复测试隔离与可复现性。
- **⑤ 能否闭环**：能。H2 跑 104 条日志 0 条 bad SQL；`data-check.sh` 残留 0；prod profile 指向隔离库时测试应拒绝启动（预期失败即通过）。

#### P0-2 开发/演示默认 JWT 密钥公开，且强校验黑名单未覆盖

- **① 问题描述**：`application.yml` dev profile 默认 `dev-only-key-please-replace-in-production-0123456789`，`env.sh` 默认 `local-dev-...`；`JwtService` 只拦截 `carbonbal-dev-secret`，两个实际默认值都能通过长度校验。演示默认以 dev 启动并监听 8088，知道仓库的人可自签任意 `org/role/pages` 令牌。
- **② 测试 bug 点**：`platform/backend/src/main/resources/application.yml:93`；`platform/env.sh:5`；`platform/backend/src/main/java/com/carbonbal/auth/JwtService.java:21-25`。
- **③ 最优修改方案**：删除所有默认密钥；dev 启动生成一次性随机密钥并打印；强校验改为"长度+熵+已知前缀"组合；演示启动绑定 127.0.0.1；新增单测断言默认值被拒。
- **④ 修改目的**：消除令牌伪造与跨租户越权。
- **⑤ 能否闭环**：能。用旧默认密钥签发的令牌访问 `/api/auth/me` 应 401；无 `JWT_SECRET` 启动应失败或使用随机值。

#### P0-3 交付包与受审源码不同源，客户拿到旧版本（项目已登记、尚未闭环）

- **① 问题描述**：`dist/carbonbal-1.0.1.zip` 构建于 2026-11-25 21:47，MANIFEST 为 `flyway=105`、23 个迁移、13 个测试类、397 个文件；当前源码为 32 个迁移（V114）、26 个测试类、104 条测试。包内缺 `functional-cases.py`、`run-prod.sh`，且 `HANDOVER.md` 的 `61/61`、`Flyway 105（23 个迁移）` 描述的正是旧包。`test-plan` 观察项已记录"dist 待发版指令重打"，属已知未闭环项，但仍是发版阻断。
- **② 测试 bug 点**：`dist/carbonbal-1.0.1/MANIFEST.txt`；`HANDOVER.md:3`、`HANDOVER.md:113-121`；`platform/tools/package-source.sh`。
- **③ 最优修改方案**：从当前源码 `mvn clean package` 后重打 dist；`package-source.sh` 增加同源校验（迁移数=源码数、测试类数、VERSION、SHA256）；HANDOVER 数字由构建脚本生成；旧包删除或改名为 `-rc`。
- **④ 修改目的**：保证交付物与受审代码一致，避免客户部署缺少 V106-V114 修复的旧版本。
- **⑤ 能否闭环**：能。重打包后 MANIFEST 为 `flyway=114/32/26`，包含两个缺失脚本，`sha256sum -c` 全 OK，`mvn test` 104/104。

### 高（P1）

#### P1-1 同集团兄弟企业数据越权读取

- **① 问题描述**：`/api/group/summary` 把当前企业 parent 下所有兄弟企业纳入统计，返回排放、能耗、设备数、成员数；接口有 `group.overview` 页面门禁，但默认角色"拥有全部页面"，普通成员即可读取同集团其他工厂数据。
- **② 测试 bug 点**：`GroupService.java:43-52`；`PageCatalog.java:79`；`RoleService.java:240`。
- **③ 最优修改方案**：新增集团级权限点或"集团管理员"成员标记；默认角色不授予 `group.overview`；查询前校验目标 org 在授权范围内。
- **④ 修改目的**：防止集团内跨企业数据泄露。
- **⑤ 能否闭环**：能。普通成员 GET 应 403；集团管理员仅返回授权工厂；补 TenantIsolationTest 用例。

#### P1-2 页面权限声明缺失时 fail-open

- **① 问题描述**：JWT 无 `pages` 声明时按 `"*"` 放行全部页面；代管令牌 `imp` 也跳过页面校验。旧令牌或声明缺失令牌获得全页面权限。
- **② 测试 bug 点**：`JwtAuthFilter.java:98-101`。
- **③ 最优修改方案**：缺失 `pages` 视为空集并拒绝；代管单独白名单；令牌结构升级时强制重新登录。
- **④ 修改目的**：权限默认拒绝，避免 fail-open。
- **⑤ 能否闭环**：能。构造无 pages 令牌访问业务接口应 403，新增单测。

#### P1-3 X-Forwarded-For 可伪造，登录锁定可绕过

- **① 问题描述**：`clientIp()` 直接取 XFF 第一段，锁定键为 `account|ip`；每次请求更换 XFF 即可无限尝试密码，5 次锁定失效。
- **② 测试 bug 点**：`AuthController.java:652-655`、`:91-93`。
- **③ 最优修改方案**：仅信任配置的反代地址，取最后一个可信代理追加的 IP；增加账号维度锁定；限制 XFF 层级。
- **④ 修改目的**：恢复撞库与爆破防护。
- **⑤ 能否闭环**：能。连续 6 次错误密码且轮换 XFF 仍应 423/429。

#### P1-4 幂等过滤器对 multipart 与大请求直接放行

- **① 问题描述**：`IdempotencyFilter` 对 multipart 与超过 256KB 的 body 直接放行，导入、附件、长表单可重复提交。
- **② 测试 bug 点**：`IdempotencyFilter.java:34`、`:39`、`:53-54`。
- **③ 最优修改方案**：multipart 以文件哈希+表单字段生成幂等键；大 body 流式哈希；关键创建接口补数据库唯一约束。
- **④ 修改目的**：防止重复落库与重复副作用。
- **⑤ 能否闭环**：能。同键 300KB JSON/multipart 重复提交只落一条或 409。

#### P1-5 前端存储型 XSS（桑基图与提示框）

- **① 问题描述**：桑基图节点文本 `${n.name}` 未转义直接插入 SVG `<text>`；tooltip 将已解码的 `dataset` 值回填 `innerHTML`。供应商/产品名可控，可注入事件处理器。
- **② 测试 bug 点**：`自研原型/assets/pages-generic.js:1036`、`:1060-1062`。
- **③ 最优修改方案**：SVG 文本用 `textContent` 或 `esc()`；tooltip 用 `textContent` 构建；名称增加字符白名单。
- **④ 修改目的**：防止会话窃取与数据泄露。
- **⑤ 能否闭环**：能。以 `<img src=x onerror=alert(1)>` 命名，打开图表与悬浮无脚本执行。

#### P1-6 bootstrap 全量载入报告 PDF（BLOB）

- **① 问题描述**：`reportRows()` 用 `selectList` 取 Report 全字段，`Report.content` 为 `byte[]` 全量 PDF，实际只用元数据；报告累积后 bootstrap 体积与堆内存线性增长，与 60KB 预算冲突。
- **② 测试 bug 点**：`BootstrapService.java:631-632`；`Report.java:25`。
- **③ 最优修改方案**：查询只 select 元数据列；`content` 仅下载接口读取；Mapper 增加投影 DTO。
- **④ 修改目的**：控制首屏体积与内存。
- **⑤ 能否闭环**：能。造 100 份报告后 `/api/bootstrap` 仍 ≤60KB，perf PT-03 通过。

#### P1-7 冒烟门禁因验证码改造失效

- **① 问题描述**：`smoke.sh` 登录只发 phone/password；`AuthController:95` 强制 `captcha.verifyLogin`，默认开启。冒烟第 2 项必 400，后续 7 项无 token 全失败；文档仍写 9/9。
- **② 测试 bug 点**：`smoke.sh:12-13`；`AuthController.java:95`；`CaptchaService.java:39-42`。

- **④ 修改目的**：恢复上线冒烟门禁，消除"脚本存在但从未跑通"。
- **⑤ 能否闭环**：能。启动服务后 smoke 9/9，失败退出码非 0。

#### P1-8 E2E 红灯常态化，审批主链无端到端保护

- **① 问题描述**：e2e 长期 100/102（今日项目侧记录 101/102），失败集中在短信登录，被写入验收基线作"环境豁免"；ui-flows 38 项未覆盖核算复核/批准/锁定；check-ui 只渲染不操作。关键审批链没有端到端用例，且门禁未要求 failed=0。
- **② 测试 bug 点**：`e2e.sh:524-525`；`docs/test-plan-2026-11-27.md:13`、§八；`自研原型/tools/ui-flows.cjs`。

- **④ 修改目的**：让门禁真实反映质量，保护核心审批链。

#### P1-9 无覆盖率、无 CI、无版本控制

- **① 问题描述**：pom 无 JaCoCo/PIT；无 CI 配置；交付目录非 git 仓库。104 条测试覆盖哪些分支未知，变更不可追溯，门禁依赖人工串联。
- **② 测试 bug 点**：`pom.xml:115-144`；根目录无 `.git`/`.github`。
- **③ 最优修改方案**：接入 JaCoCo（行/分支阈值）与 PIT（核算/权限核心域）；建立 git 与 CI，至少执行 mvn test+gate-l0+smoke；发布只允许 CI 产物。
- **④ 修改目的**：质量可度量、变更可追溯、门禁可强制。
- **⑤ 能否闭环**：能。CI 每次提交产出覆盖率与门禁报告，覆盖率达标。

#### P1-10 测试之间无隔离，顺序依赖被掩盖

- **① 问题描述**：26 类共享一个 Spring 上下文与 H2；清理失效；`@Order` 与全局种子数据造成顺序依赖；12 个类用 `@DirtiesContext` 仅局部缓解；用例仍全绿属于"顺序正确"而非"相互独立"。
- **② 测试 bug 点**：`ApiTestSupport.java:20-22`；`AccountingFlowTest.java:24-38`。
- **③ 最优修改方案**：每类事务回滚或 `@Sql` 重置；移除 `@Order`；测试数据唯一前缀并在 `@AfterEach` 清理；增加一组 Testcontainers MySQL 迁移/集成测试。
- **④ 修改目的**：保证任意顺序、单类运行均可复现。
- **⑤ 能否闭环**：能。随机顺序 104 条全绿，单类运行全绿。
